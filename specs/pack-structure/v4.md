# 整合包容器 v4（现行）

v4 是标准 ZIP，扩展名为 `.dspack`。根目录必须含 UTF-8 JSON 标记 `{"format":"dspack","version":4}` 以及 `manifestVersion: 6` 的 `manifest.json`。顶层不再套包名目录。读取器应在写入目标前检查版本配对、所有相对路径、扩展引用和内容摘要。[清单 v6](../manifest/v6.md)

## 1. 归档布局

| 归档路径 | 用途与安装目标 |
| --- | --- |
| `dspack.json`、`manifest.json` | 容器标记与整合包清单 |
| `package.json`、`pnpm-workspace.yaml`、`pnpm-lock.yaml` | 单 profile 可选的机器文件快照，依赖与层栈以本 profile 清单重建 |
| `overrides/` | `profile` 对应目标 profile 根。`dshhome` 对应 DSH_HOME 根，其中 `profiles/<名称>/` 是各 profile 的文件 |
| `home/` | 单 profile 包选择的 DSH_HOME 级文件 |
| `assets/plugins/` | 归档内展示图标，仅供预览或按图标引用提取 |
| `vendor/` | `vendored` 登记的依赖 tarball，须核验坐标、版本、大小与摘要 |
| `path.json`、`provider.json`、`mcp.json`、`skill.json` | 导出时选择的插件数据、模型服务商、MCP 服务和技能。未选择某类资源时可省略相应文件 |
| `extension-data/path/<sha256>`、`extension-data/skill/<sha256>` | 附件引用的原始文件字节，相同内容可共用一份 |

`overrides/`、`home/`、基础 `patch` 与附件之间不能重复携带专业清单负责的配置或文件；尤其不能在普通快照里保留移出的凭据。禁止附带本机 `.npmrc`、`.env`、`.credentials.yaml`、包管理器凭证、安装基线及专用源缓存。安装专用源仅影响声明的精确依赖，原有 scoped registries 保留。普通文件过滤与旧版本目录语义见[容器 v3](v3.md)。

## 2. 首次安装

1. 读取下载大小与归档 SHA-256（如已知），验证容器标记、manifest、目标 profile 和兼容性声明。
2. 在独立暂存目录展开普通内容。检查专业附件的引用、技能来源与文件摘要；拒绝绝对路径、上跳、越界链接以及多个条目争用同一目标。
3. 展示各资源的名称、描述、作用域、目的地、冲突与缺少的凭据，允许逐项保留、替换或跳过。缺少必需凭据的配置可以跳过，其余资源可继续安装。
4. 根据每个 profile 的 `dependencies` 与 `plugins[id].source` 解析依赖。重建层栈，完成安装时记录归档摘要、已托管文件与配置基线。凭据由本机单独保存。

## 3. 已有目标与更新

先确定包身份、目标 profile/home 和旧基线，再比较基线、当前文件和新包。来源、profile 名、包版本等身份不匹配时不能把其他包的状态当作旧基线。没有历史状态的旧安装可由经过 SHA-256 核验的原包重建基线，否则按未知基线处理，同名既有文件默认保留。

| 三方结果 | 默认行为 |
| --- | --- |
| 当前内容等于新包 | 保留现状 |
| 上游未变，本地已改 | 保留本地 |
| 本地等于基线，上游替换或删除 | 更新或移除原包拥有的文件 |
| 本地和上游都变更 | 对支持的 JSON、YAML 配置合并独立成员。重叠修改列为冲突，默认保留本地 |
| 新包碰到未托管或其他包共用的目标 | 显示冲突或保留共享文件，禁止按包卸载关系任意删除 |

预览返回变更和冲突清单。使用上游版本处理冲突之前须确认相应的预览；实际写入前再次核对本地状态，过期预览必须重做。写入、依赖重建和新基线记录应作为一次可回滚的操作。可选扩展中被跳过或显式保留的路径也必须参与保护。交互决定、凭据值和本机基线不进入分发归档。

## 4. 版本识别

新导出统一使用 v4 / manifest v6。旧容器 v3 与 manifest v5 继续按其原格式读取。旧包的普通文件、技能或补丁不能直接当成新版四类专业附件，市场可以继续索引旧包。规范示例提供[两个可校验的归档根目录](../../examples/v6/)。
