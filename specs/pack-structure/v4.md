# 整合包容器规范 v4（pack-structure v4，现行）

> 状态：**现行**。v4 容器对应 `manifestVersion: 6`，定义 `.dspack` 归档的目录布局、安装校验与三方更新合并规则。
>
> 关联：[清单规范 v6](../manifest/v6.md) · [插件数据与可选资源规范 v1](../dsh_pack/v1.md) · [容器 v3（历史）](v3.md)

v4 是标准 ZIP 归档文件，扩展名为 `.dspack`。归档根目录必须包含 UTF-8 JSON 格式的容器标记 `{"format":"dspack","version":4}` 与 `manifestVersion: 6` 的 `manifest.json`；所有文件直接置于归档根目录，不再包裹以包名命名的顶层目录。读取器在写入任何目标文件之前，须完整校验版本配对、相对路径合法性、资源引用及内容摘要。

## 1. 归档布局

| 归档路径 | 用途与安装目标 |
| --- | --- |
| `dspack.json`、`manifest.json` | 容器版本标记与整合包清单 |
| `package.json`、`pnpm-workspace.yaml`、`pnpm-lock.yaml` | 单配置档（profile）可选的环境快照；实际依赖与层栈均以清单为准重建 |
| `overrides/` | `profile` 形态映射至目标配置档根目录；`dshhome` 形态映射至 `DSH_HOME` 根目录（其中 `profiles/<名称>/` 存放各配置档文件） |
| `home/` | 单配置档整合包附带的 `DSH_HOME` 级文件 |
| `assets/plugins/` | 归档内嵌的插件展示图标，仅供市场预览或按插件图标引用提取 |
| `vendor/` | `vendored` 字段登记的依赖压缩包（tarball），安装时须核验坐标、版本、大小与摘要 |
| `path.json`、`provider.json`、`mcp.json`、`skill.json` | 导出时勾选的插件数据路径、模型服务商（Provider）、MCP 服务与技能清单；未勾选某类资源时可省略对应文件 |
| `extension-data/path/<sha256>`、`extension-data/skill/<sha256>` | 资源清单引用的原始文件内容，相同字节内容可共用同一条目 |

### 隔离与过滤约束

- `overrides/`、`home/`、基础补丁（base patch）与四类可选资源清单之间不得重复携带同一配置或文件，尤其严禁在常规快照中残留已被剥离的凭据（credential）。部分导出 `DSH_HOME` 时，选中配置档的 `cordis.patch.yml` 也须选中同目录的 `package.json`，以便按所属配置档剥离服务配置。若缺少该文件，导出器须指出缺失路径并中止导出。
- 禁止随包分发本机 `.npmrc`、`.env`、`.credentials.yaml`、包管理器凭据、安装基线文件及专用包源（registry）缓存。
- 安装专用源仅作用于清单中显式声明的精确依赖，目标机原有的 scoped registry 配置保持不变。常规文件过滤规则与旧版目录语义见[容器 v3](v3.md)。

## 2. 首次安装流程

1. 读取下载大小与归档 SHA-256（如已知），校验容器标记、`manifest.json`、目标配置档及兼容性声明。
2. 在独立暂存目录中解压常规文件，逐项核验可选资源的引用关系、技能来源与文件摘要；拒绝绝对路径、目录上跳（`..`）、越界符号链接以及多个条目争用同一目标路径的归档。
3. 向用户展示各资源的名称、简介、作用域（scope）、目标位置、潜在冲突与缺失凭据，支持逐项选择保留、替换或跳过。缺少必需凭据的条目可跳过，其余资源继续安装。
4. 按每个配置档的 `dependencies` 与 `plugins[id].source` 解析依赖并重建插件层栈；安装完成时在本机记录归档摘要、已托管文件清单与配置基线。用户输入的凭据仅保存在本机安全存储中。

## 3. 已有目标与更新合并

更新前须先确认整合包身份、目标配置档或 `DSH_HOME` 位置以及历史安装基线（baseline），再对比「安装基线、本机当前内容、新包内容」三方状态：

- 来源、配置档名称或包标识不匹配时，不得将其他整合包的状态误作当前基线。
- 若旧版安装未留存基线，可通过经过 SHA-256 校验的原版整合包重建基线；否则按「未知基线」处理，同名既有文件默认保留本机版本。

| 三方对比结果 | 默认处理策略 |
| --- | --- |
| 当前内容与新包一致 | 保持现状 |
| 上游未变更，本机已修改 | 保留本机修改 |
| 本机与基线一致，上游替换或删除 | 同步更新或移除原包托管的文件 |
| 本机与上游均已修改 | 对支持的 JSON、YAML 配置按独立成员自动合并；重叠修改标记为冲突，默认保留本机 |
| 新包涉及未托管文件或其他整合包共用的目标 | 提示冲突或保留共享文件，禁止按包卸载关系擅自删除 |

### 预览与事务保障

- 更新预览应返回完整的变更与冲突清单；选择采用上游版本覆盖冲突前，须先确认对应的预览结果。
- 实际写入磁盘前须再次核对本机状态，若本地文件在预览后发生变化则判定预览过期，必须重新生成。
- 文件写入、依赖重建与新基线落盘应作为一个可回滚的原子操作执行；可选资源中被跳过或显式保留的路径同样受保护。
- 用户的交互决策、凭据实值与本机基线均只留存本地，绝不写入分发归档。

## 4. 版本识别与示例

新导出归档统一使用容器 v4 与清单 v6；旧版容器 v3 与清单 v5 继续按原格式解析。旧版整合包中的常规文件、技能目录或补丁不得直接套用新版四类可选资源的语义，市场索引可继续收录旧包。规范仓库提供了[单配置档与全局目录两个可校验示例](../../examples/v6/)供参考。
