# Pack Structure v2 规格说明（未来）

> 状态：**未来（尚未实现）**。`.dspack` 容器 = **ZIP 内核 + `DSPK` 头部 + `overrides/` 布局**，格式模仿 Modrinth 的 mrpack。承载 manifest v4（`../manifest/v4.md`）。
>
> 关联：`../pack-structure/v1.md`（现行 `.tgz` 格式，本文是它的演进）、`../manifest/v4.md`（本文容器的索引契约）、`ModPack-CLI/docs/architecture.md`（L1→L3 演进）。

---

## 1. 概述

v2 把「容器」从 v1 的 `.tgz` 换成 **`.dspack`**，并在结构上模仿 Modrinth mrpack `（modrinth.index.json + overrides/）` 的两个关键分离：

- **索引单一化**：归档根只放一个 `manifest.json`，其余用户文件全进 `overrides/`；
- **内容指针化**：重内容不进包体，由 manifest 的 `files[]` 记 `path + sha256 + size + urls[]`，安装时按需拉取。

同时为 `.dspack` 写入**头部魔术字节**，使后缀即使被改成 `.zip` 也能被加载器一眼识别、拒载或报损坏。

---

## 2. 容器与文件头

### 2.1 文件名

```
<manifest.name>-<manifest.version>.dspack
```

例如 `all-about-whales-1.0.0.dspack`。

### 2.2 头部（魔术字节）

文件前 8 字节为固定头，其后是标准 ZIP 负载：

| 偏移 | 内容 | 说明 |
| --- | --- | --- |
| `0x00–0x03` | `DSPK` | 魔术字节（ASCII：`44 53 50 4B`） |
| `0x04–0x07` | uint32 LE = `2` | 容器格式版本（对应本文 pack-structure v2） |
| `0x08–EOF` | 标准 ZIP 流 | 见 §3 布局 |

**加载器判定：**

1. 读前 8 字节；前 4 字节 ≠ `DSPK` → **不是 dspack**（被改后缀 / 外来 ZIP / 损坏）→ 拒载并报错；
2. 版本字段 ≠ 2 → 报「不支持该 `.dspack` 版本」；
3. 通过 → 把 `字节[8:]` 当标准 ZIP 处理。

> 权衡：加前导后文件头不再是 `PK\x03\x04`，严格看不算裸 ZIP；但 ZIP 的目录在文件末尾（EOCD），7-Zip / Windows 资源管理器等宽容工具通常仍能直接打开。自有读写器永远先剥 8 字节，不受影响。整包 `sha256` 覆盖「头部 + ZIP」全量字节。

## 3. 归档内部布局（ZIP 内）

```
all-about-whales-1.0.0.dspack
├── [头部 8B] DSPK + version=2
└── ZIP 内:
    ├── manifest.json        # ★ 索引（根，manifest v4）
    ├── package.json         # 可选快照（安装时被 manifest 权威重建）
    ├── pnpm-workspace.yaml  # 可选
    ├── pnpm-lock.yaml       # 可选
    └── overrides/           # 用户文件，安装时覆盖进 profile 根
        ├── cordis.patch.yml
        ├── skills/…
        ├── data/…
        └── icons/…
```

> 关键约定：**ZIP 根必须包含 `manifest.json`**（安装端硬性前提）。用户文件一律放 `overrides/`，根目录只留机器文件（manifest / package / pnpm 设置）。

---

## 4. 归档内容清单

| 类别 | 文件 | 说明 |
| --- | --- | --- |
| 必有 | `manifest.json` | v4 契约头（含 `type` / `bundles` / `dependencies` / 可选 `files[]`） |
| 可选 | `package.json` | Profile 快照（安装时被 manifest 权威重建） |
| 可选 | `pnpm-workspace.yaml` / `pnpm-lock.yaml` | 工作区设置 / 传递依赖锁定 |
| 必有（目录） | `overrides/` | 用户文件，覆盖进 profile 根（见 §5） |
| 不打包 | `node_modules` 等 | 依赖由 `pnpm install` 重建；重内容走 `files[]` 按需拉取 |

---

## 5. overrides/ 语义

`overrides/` 是「随包携带、安装时覆盖到 profile 根」的目录，对应 mrpack 的 `overrides/`：

- `overrides/xxx` → 安装时写到 `<profile>/xxx`；
- 例：`overrides/cordis.patch.yml`、`overrides/skills/…`、`overrides/data/…`、`overrides/icons/…`；
- 以 manifest 为唯一事实源：与 manifest 冲突的机器字段（`bundles` / `dependencies`）由 manifest 权威重建，`overrides/` 只承载「用户自定义配置文件」。

---

## 6. files[] 下载（重内容按需拉取）

- 定义见 `../manifest/v4.md` §3：`{ path, sha256, size, urls[] }`。
- 安装时逐个下载到 `path`（相对 profile 根），校验 `sha256` + `size`；任一失败 → 删除已下文件并整体回滚。
- 常规插件走 npm / git（`bundles` + `dependencies`），**不**进 `files[]`；`files[]` 只用于模型、数据、非 npm/git 二进制等重内容。

---

## 7. 安全过滤（沿用 v1）

`overrides/` 内的文件在打包时沿用 v1 的四类安全过滤（`security.js`）：`node_modules` / `.env` / 密钥凭据 / 嵌套压缩包等一律排除。重内容通过 `files[]` 指针分发后，归档体积得以保持几十 KB ~ 几 MB。

---

## 8. 安装端行为

1. 校验头部 `DSPK` + version=2 → 剥离 8 字节解 ZIP 到临时目录；
2. 读 `manifest.json`（校验 v4 且 `type === "profile"`）；
3. `overrides/` 覆盖到 profile 根；
4. 按 `dependencies` 转 `package.json` → `pnpm install`（优先 frozen-lockfile）；
5. 逐条 `files[]` 下载 + 校验 `sha256` / `size`，失败回滚；
6. `reconcileProfile` 对账（缺 bundle → 回滚）。

## 9. 与 v1 / 路线图的关系

| 版本 | 容器 | 内容 | 状态 |
| --- | --- | --- | --- |
| v1 | `.tgz` | 扁平快照 + 根 `manifest.json` | **现行**（`pack-structure/v1.md`） |
| **v2** | `.dspack`（ZIP + DSPK 头） | `manifest.json` + `overrides/` + 可选 `files[]` | **未来**（本文） |

> 本文把 architecture.md 的 L2（zip + overrides）与 L3（重内容 `assets[]` 按需拉取）合一落地为 `files[]`。索引与存储的「指针制」分工不随容器变化而改变。

---

## 10. 结论

> `.dspack` = **ZIP 内核 + `DSPK` 头部 + `overrides/` 布局 + 可选 `files[]` 按需拉取**，头部魔术字节保证格式可被可靠识别，`overrides/` 让机器文件与用户文件各归其位，`files[]` 让重内容也进入「指针 + sha256」的完整性闭环——是在 v1 之上的平滑演进，模仿 mrpack 而不失 DSH 自身的层栈契约。
