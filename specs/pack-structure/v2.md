# Pack Structure v2 规格说明（现行）

> 状态：**现行**。`.dspack` 容器 = **纯 ZIP 内核 + 根 `dspack.json` 标记文件 + `overrides/` 布局**，格式模仿 Modrinth 的 mrpack。承载 manifest v4（`../manifest/v4.md`）。生成侧 `dsh-packforge-app` 与参考实现 `all-about-whales` 均以 `.dspack` 产出。
>
> 关联：`../pack-structure/v1.md`（历史 `.tgz` 格式，本文是它的演进）、`../manifest/v4.md`（本文容器的索引契约）、`dsh-packforge-app` 实现（L1→L2→L3 演进）。

---

## 1. 概述

v2 把「容器」从 v1 的 `.tgz` 换成 **`.dspack`**，并在结构上模仿 Modrinth mrpack `（modrinth.index.json + overrides/）` 的两个关键分离：

- **索引单一化**：归档根只放一个 `manifest.json`，其余用户文件全进 `overrides/`；
- **内容指针化**：重内容不进包体，由 manifest 的 `files[]` 记 `path + sha256 + size + urls[]`，安装时按需拉取。

容器本身是**标准 ZIP**（文件头就是 `PK\x03\x04`，压缩软件可直接打开）；「这是不是 dspack、以及容器版本」由根目录的 **`dspack.json` 标记文件**承载，替代早期的前导魔术字节。

---

## 2. 容器与标识文件

### 2.1 文件名

```
<manifest.name>-<manifest.version>.dspack
```

例如 `all-about-whales-1.0.0.dspack`。

### 2.2 标识文件 `dspack.json`（ZIP 根，必有）

ZIP 根目录放一个标记文件 `dspack.json`，用于识别容器与版本：

```json
{
  "format": "dspack",
  "version": 2
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `format` | string | 固定 `"dspack"`，容器标识 |
| `version` | number | 容器格式版本，对应本文 pack-structure v2 |

**加载器判定：**

1. 直接按标准 ZIP 打开（首两字节即 `PK`）；
2. 读根 `dspack.json`：缺失 / 非对象 → **不是 dspack**（外来 ZIP / 损坏）→ 拒载并报错；
3. `format` ≠ `"dspack"` 或 `version` ≠ 2 → 报「不支持该 `.dspack` 版本」；
4. 通过 → 按 §3 布局处理。

> 权衡：容器就是裸 ZIP，任何压缩软件都能直接打开、浏览；识别职责从「文件头字节」移到「根标记文件」。整包 `sha256` 覆盖 ZIP 全量字节（与普通文件一致，无剥离步骤）。

## 3. 归档内部布局（ZIP 内）

```
all-about-whales-1.0.0.dspack
└── ZIP 内:
    ├── dspack.json         # ★ 容器标记（format + version）
    ├── manifest.json       # ★ 索引（根，manifest v4）
    ├── package.json        # 可选快照（安装时被 manifest 权威重建）
    ├── pnpm-workspace.yaml # 可选
    ├── pnpm-lock.yaml      # 可选
    └── overrides/          # 用户文件，安装时覆盖进 profile 根
        ├── cordis.patch.yml
        ├── skills/…
        ├── data/…
        └── icons/…
```

> 关键约定：**ZIP 根必须包含 `dspack.json` 与 `manifest.json`**（安装端硬性前提）。用户文件一律放 `overrides/`，根目录只留容器/机器文件（dspack / manifest / package / pnpm 设置）。

---

## 4. 归档内容清单

| 类别 | 文件 | 说明 |
| --- | --- | --- |
| 必有 | `dspack.json` | 容器标记文件（`format` / `version`） |
| 必有 | `manifest.json` | v4 契约头（含 `type` / `bundles` / `dependencies` / 可选 `files[]`） |
| 可选 | `package.json` | Profile 快照（安装时被 manifest 权威重建） |
| 可选 | `pnpm-workspace.yaml` / `pnpm-lock.yaml` | 工作区设置 / 传递依赖锁定 |
| 必有（目录） | `overrides/` | 用户文件，覆盖进 profile 根（见 §5） |
| 不打包 | `node_modules` 等 | 依赖由 `pnpm install` 重建；重内容走 `files[]` 按需拉取 |

---

## 5. overrides/ 语义

`overrides/` 是「随包携带、安装时写到 profile 根」的目录，对应 mrpack 的 `overrides/`：

- `overrides/xxx` → 安装时写到 `<profile>/xxx`，**同名即整文件覆盖（替换）**；
- 例：`overrides/cordis.patch.yml`、`overrides/skills/…`、`overrides/data/…`、`overrides/icons/…`；
- 以 manifest 为唯一事实源：与 manifest 冲突的机器字段（`bundles` / `dependencies` / `package.json` / `pnpm-lock`）由 manifest 权威重建，**不进 overrides**；`overrides/` 只承载「用户自定义配置文件」。

**「覆盖」是文件级复制替换，不是语义合并：** `overrides/` 不解析文件内容做字段级 merge，而是整文件复制过去、同名盖掉。真正做「合并式覆盖」的是 `cordis.patch.yml`（Cordis 补丁层，安装后由加载器在 bundle 层之上应用）——两者层次不同：前者是文件摆放，后者是配置补丁。

> 为何通常「没多少可替换」：全新 profile 的机器文件由 manifest 重建，overrides 里又只有用户自有文件，两边几乎不同名，所以 overrides 多数时候是「放置」而非「替换」；「overrides」之名沿用 mrpack 惯例。

---

## 6. files[] 下载（重内容按需拉取）

- 定义见 `../manifest/v4.md` §3：`{ path, sha256, size, urls[] }`。
- 安装时逐个下载到 `path`（相对 profile 根），校验 `sha256` + `size`；任一失败 → 删除已下文件并整体回滚。
- 常规插件走 npm / git（`bundles` + `dependencies`），**不**进 `files[]`；`files[]` 只用于模型、数据、非 npm/git 二进制等重内容。

---

## 7. 安全过滤（沿用 v1）

`overrides/` 内的文件在打包时沿用 v1 的四类安全过滤（`security.js`）：`node_modules` / `.env` / 密钥凭据 / 嵌套压缩包等一律排除。重内容通过 `files[]` 指针分发后，归档体积得以保持几十 KB ~ 几 MB。

---

## 8. 安装端行为

1. 按标准 ZIP 解包到临时目录 → 校验根 `dspack.json`（`format === "dspack"` 且 `version === 2`）；
2. 读 `manifest.json`（校验 v4 且 `type === "profile"`）；
3. 按 `dependencies` 转 `package.json` → `pnpm install`（优先 frozen-lockfile）；
4. `overrides/` 覆盖到 profile 根（用户文件最后落盘，压过运行时/依赖默认项）；
5. 逐条 `files[]` 下载 + 校验 `sha256` / `size`，失败回滚；
6. `reconcileProfile` 对账（缺 bundle → 回滚）。

## 9. 与 v1 / 路线图的关系

| 版本 | 容器 | 内容 | 状态 |
| --- | --- | --- | --- |
| v1 | `.tgz` | 扁平快照 + 根 `manifest.json` | **历史**（`pack-structure/v1.md`） |
| **v2** | `.dspack`（纯 ZIP + 根 `dspack.json`） | `manifest.json` + `overrides/` + 可选 `files[]` | **现行**（本文） |

> 本文把 L2（zip + overrides）与 L3（重内容 `assets[]` 按需拉取）合一落地为 `files[]`。索引与存储的「指针制」分工不随容器变化而改变。

---

## 10. 结论

> `.dspack` = **纯 ZIP 内核 + 根 `dspack.json` 标记 + `overrides/` 布局 + 可选 `files[]` 按需拉取**。标准 ZIP 保证压缩软件可直接打开，根标记文件保证格式可被可靠识别与版本演进，`overrides/` 让机器文件与用户文件各归其位，`files[]` 让重内容也进入「指针 + sha256」的完整性闭环——在 v1 之上的平滑演进，模仿 mrpack 而不失 DSH 自身的层栈契约。
