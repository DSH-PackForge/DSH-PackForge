# Pack Structure v1 规格说明（历史）

> 状态：**历史（L1：单 `.tgz`，仍兼容导入）**。本文规范整合包（`.tgz`）的**文件布局、扫描规则、安全过滤、打包流程与安装端结构前提**。`.dspack`（`../pack-structure/v2.md`）为其现行演进。
>
> 代码定位：`ModPack-CLI/packages/modpack/src/scan.js`（扫描）、`security.js`（过滤）、`pack.js`（打包）、`install.js`（安装端前提）。
>
> 关联：`../manifest/v2.md`（manifest 契约，归档内的 `manifest.json`）、`../pack-structure/v2.md`（`.dspack` 现行格式）。

---

## 1. 概述

一个整合包 = **一个 `.tgz` 归档**，内容是「DSH Profile 的**扁平文件快照**（剔除易失/敏感文件）+ 一份 `manifest.json` 契约头」。

- **扁平布局**：归档内**没有顶层包裹目录**，文件直接按 Profile 内的相对路径平铺在归档根。
- **轻量**：剔除 `node_modules` 等依赖目录（安装时由 `pnpm install` 重建），包体通常几十 KB ~ 几 MB。
- **契约 + 快照双轨**：`manifest.json` 是「唯一事实源」，`package.json` / `cordis.patch.yml` 只作快照（安装时被 manifest 权威覆盖重建）。

---

## 2. 产物与顶层布局

### 2.1 文件名

```
<manifest.name>-<manifest.version>.tgz
```

例如 `web-1.0.0.tgz`（`name` 为规范化的 slug，`version` 为 semver）。

### 2.2 归档内部布局（扁平）

```
web-1.0.0.tgz
├── manifest.json          # ★ 契约头（打包时生成，始终在根）
├── package.json           # Profile 快照
├── cordis.patch.yml       # 配置补丁快照
├── pnpm-workspace.yaml    # 可选（DSH Profile 通常携带）
├── README.md              # 任意文件，随包分发
├── icons/logo.png         # 图标（manifest.icon 指向的相对路径）
├── skills/…               # 任意自定义目录（DSH 技能体系）
└── data/…                 # 任意自定义目录（L2/L3 的数据雏形）
```

> 关键约定：**归档根必须包含 `manifest.json` 与 `package.json`**（安装端硬性前提，见 §6）。其余文件按 Profile 目录的相对路径原样保留。

---

## 3. 归档内容清单

| 类别 | 文件 | 说明 |
|---|---|---|
| 必有 | `manifest.json` | 契约头，`buildManifest` 生成 |
| 必有 | `package.json` | Profile 快照（`dependencies` / `dsh.profile.bundles` 由 manifest 权威重建） |
| 常态携带 | `cordis.patch.yml` | 配置补丁原文快照 |
| 常态携带 | `pnpm-workspace.yaml` | DSH Profile 工作区配置 |
| 任意 | `README.md`、`icons/*`、`skills/*`、`data/*` 等 | **任何未命中过滤规则的文件**都随包分发 |
| 剔除 | `node_modules` 等依赖/生成/敏感文件 | 见 §5 安全过滤，安装时重建 |

> 架构含义：`skills/`、`data/` 等自定义目录**现在就能**随包分发（无需等待 zip 格式），是 L2/L3 的前置基础。

## 4. 扫描规则（`scan.js`）

`scanProfile(profileDir)` 递归遍历 Profile 目录，产出 `{ files, excluded }`：

- `files`：`{ rel, abs, size }[]`，按 `rel` 用 `localeCompare` 升序排序；
- `excluded`：`{ rel, reason }[]`，`reason` 为 `'symlink'` 或 `'deny'`。
- **路径分隔符统一为 `/`**（`relPath = \`${rel}/${entry.name}\``），即使运行在 Windows。
- **符号链接一律跳过**（`reason: 'symlink'`）——防止逃出 Profile 目录与死循环。
- 无法 `readdir`（无权限）的目录 → 跳过；无法 `stat`（读大小失败）的文件 → 记 `size: 0` 并跳过。
- 目录/文件一旦命中 `isExcluded`（`security.js`）→ 记入 `excluded`（`reason: 'deny'`），整目录跳过递归。

---

## 5. 安全过滤规则（`security.js`）

`isExcluded(relPath)` 四类规则，任一命中即排除：

### 5.1 精确名称（`DENY_EXACT`，**匹配任一路径段**，任意深度）

| 分组 | 项 |
|---|---|
| 依赖 / 构建产物 | `node_modules` `dist` `build` `coverage` `.cache` `.turbo` `.pnpm-store` |
| 自动生成配置 | `cordis.yml`（安装时由 bundles + patch 重新合成） |
| 打包产物（防嵌套） | `manifest.json` |
| 其他锁文件（DSH 用 pnpm） | `package-lock.json` `yarn.lock` |
| 日志 | `npm-debug.log` `pnpm-debug.log` |
| 敏感（精确名） | `.env` `.npmrc` `.netrc` `.yarnrc` `.yarnrc.yml` `.pypirc` `.npmignore` |

### 5.2 扩展名（`DENY_EXT`，按 basename 最后一段、小写）

```
.key  .pem  .p12  .pfx  .crt  .der  .asc
```

### 5.3 文件名正则（`DENY_BASENAME`，匹配 basename）

| 模式 | 覆盖 |
|---|---|
| `^\.env(\..+)?$` | `.env` / `.env.local` / `.env.production` … |
| `(^|\.)credentials?\.ya?ml$`（i） | `credentials.yaml` / `.credentials.yml` / `my.credentials.yml` |
| `\.(credential|credentials)$`（i） | `*.credential` / `*.credentials` |
| `^id_(rsa|ed25519|ecdsa|ed448|dsa)(\.pub)?$` | SSH 私钥（及公钥） |
| `^secrets?\.(json|ya?ml)$`（i） | `secrets.json` / `secret.yml` |
| `^(api[-_]?key|apikey|token)s?([._-].*)?$`（i） | `api_key.txt` / `token.json` / `api.key` … |

### 5.4 相对路径正则（`DENY_PATH`）

```
\.tgz$   \.tar\.gz$     // 禁止嵌套打包
```

> 实测基准（`test/pack.test.js`）：标准 Profile 有 `node_modules/.env/.npmrc/credentials.yaml/id_rsa/cordis.yml` 6 项被排除（`excluded === 6`），5 个保留文件 + manifest = 6 个归档文件（`included === 6`）。

## 6. 打包流程（`pack.js`）

1. `scanProfile(profile.dir)` 扫描；
2. 若 `files.length === 0` → 报错「没有可打包的文件」（空 Profile / 全被过滤）；
3. `buildManifest(profile, opts, scan)` 生成 manifest；
4. 暂存到系统临时目录 `mkdtemp(path.join(os.tmpdir(), 'modpack-'))` → **绝不改动用户 Profile 目录**；
5. 逐个 `copyFile` 扫描文件进暂存（保留相对路径）；写 `manifest.json`（`JSON.stringify(manifest, null, 2) + '\n'`，UTF-8）；
6. 输出路径：`path.resolve(opts.out || cwd)` / `${name}-${version}.tgz`；已存在且未 `--force` → 报错；
7. `createTar({ cwd: staging, gzip: true, file: outPath, portable: true }, entries)`，`entries` = 显式文件清单（`scan.files` 的 rel + `'manifest.json'`）；
8. 返回 `{ manifest, output, sha256, size, included, excluded }`，最后清理暂存目录。

### 关键实现约定

- **`portable: true`**：tar 归档路径规范化（剥离绝对前缀、统一分隔符）。
- **显式文件清单，而非 `'.'`**：Windows 上以 `'.'` 作为归档路径不可靠（见 session-notes 坑 7）。
- **`sha256` 覆盖整个 `.tgz`**（含 manifest）→ 索引里的完整性校验能「牵一发动全身」。
- **`included = files.length + 1`**（多出的是 `manifest.json`）；**`excluded = excluded.length`**。

## 7. 安装端结构前提（`install.js`）

安装器对归档结构有两条**硬性前提**：

1. 归档根有 `manifest.json`（可解析且通过 `validateManifest`）；
2. 归档根有 `package.json`（否则「不是有效的 DSH Profile 配置」）。

满足后：以 `manifest` 为唯一事实源，`applyManifestToProfile` 覆盖重建 `package.json` 的 `dependencies` / `dsh.profile.bundles`，写回 `cordis.patch.yml`；`node_modules` 由 `pnpm install` 重建；最后 `reconcileProfile` 对账（缺失 bundle → 回滚，见 `../manifest/v2.md` §5）。

> 因此 `cordis.yml`、`node_modules` 等被剔除项**并非损失**——它们在安装端是「可再生的派生产物」。

## 8. 与 manifest / 索引的关系

| 层 | 载体 | 关键字段 |
|---|---|---|
| 整合包 `.tgz` | 归档内文件 | 本文规范：布局 + 过滤 + 打包 |
| `manifest.json` | 归档根 | `../manifest/v2.md`：`bundles` / `dependencies` / `patch` 三分离契约 |
| `index.json` | 中心仓库 | 从 manifest 平铺 + `downloadUrl` / `sha256` / `size` 等指针字段（详见 `../index/index.md`） |

指针制闭环：**内容（`.tgz`）放分布式存储，索引只记 `downloadUrl + sha256 + size`**——`sha256`/`size` 正是本文 §6 打包流程产出的两个字段。

## 9. 格式演进（L1 → L3）

| 阶段 | 包内容 | 本文适用 |
|---|---|---|
| **L1（历史）** | 单 `.tgz`：manifest + 配置 + 任意小文件 | ✅ 本文即 L1 规范 |
| L2（现行） | `.dspack`：manifest + `overrides/` + 可选 `files[]` 按需拉取 | 布局主语不变，容器换成 zip |
| L3（MC 化） | zip + 重内容声明为 assets 按需拉取 | 引入 `assets[]` 摘要 |

> 详见 `dsh-packforge-app` 实现（L1→L2→L3 演进）。**索引与存储的分工（指针制）不随格式演化而改变**。

## 10. 已知边界 / 注意事项

1. **编码（BOM 坑）**：Windows 下若生成机器文件时误写 UTF-8 BOM，`JSON.parse`（manifest/package.json）会崩溃；写机器文件须用 Node 或 `utf8NoBOM`（session-notes 坑 1）。
2. **`rel` 分隔符**：统一 `/`，与 Windows 反斜杠无关——索引/对照逻辑都依赖这一点。
3. **扁平 vs 包裹目录**：归档**不含**顶层目录，解压即散落文件；这是与 npm 包（含 `package/` 前缀）的差异，安装端 `extractTar` 直接依赖这一点。
4. **暂存区在系统临时目录**：打包/安装都用 `os.tmpdir()` 暂存，结束后 `rm -rf`，避免污染用户目录与 Profile。
5. **符号链接整体丢弃**：不做解引用；整合包目标是「可移植快照」，符号链接（尤其指向 Profile 外）一律不进入归档。

---

## 11. 结论

> 整合包结构 = **扁平 Profile 快照（过滤后）+ 根 `manifest.json` 契约头**，以 `.tgz` 为载体；扫描遵循 `/` 分隔与符号链接跳过，过滤遵循四类安全规则，打包以暂存区隔离并产出 `sha256/size` 供索引校验。一切易失/敏感/派生文件都在「剔除—重建」的对侧闭环。
