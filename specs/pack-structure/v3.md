# Pack Structure v3 规格说明（未来）

> 状态：**未来（尚未实现）**。`.dspack` v3 容器 = **纯 ZIP 内核 + 根 `dspack.json` 标记（version 3）**，**统一承载两种形态**——`type:"profile"`（单 profile，`overrides/` 落 profile 根 + 可选 `home/` 落 home 根）与 `type:"dshhome"`（整个 DSH_HOME，`overrides/` 按 home 根平铺）。承载 manifest v5（`../manifest/v5.md`）。
>
> 关联：`../pack-structure/v1.md`（现行 `.tgz`）、`../pack-structure/v2.md`（单 profile `.dspack` 前身，无 `home/`）、`../manifest/v5.md`（本文容器的索引契约）。

---

## 1. 概述

v3 把 v2 的「单 profile `.dspack`」推广为「统一容器」，在 v2 的 `overrides/`（profile 根覆盖）之外新增两个概念：

- **`home/` 目录**（profile 形态可选）：单 profile 整合包也能携带「上一级目录」（`$DSH_HOME` 根）的内容，如全局 skill / `.agent-presets`。
- **dshhome 形态**：`overrides/` 的覆盖目标从「单个 profile 根」提升为「整个 `$DSH_HOME` 根」。

容器本身是标准 ZIP（`PK\x03\x04` 开头）；「是不是 dspack、容器版本」由根 `dspack.json` 承载。

---

## 2. 容器与标识文件

### 2.1 文件名

```
<manifest.name>-<manifest.version>.dspack
```

### 2.2 标识文件 `dspack.json`（ZIP 根，必有）

```json
{ "format": "dspack", "version": 3 }
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `format` | string | 固定 `"dspack"` |
| `version` | number | 容器格式版本，统一为 `3`（profile 与 dshhome 共用） |

**加载器判定（同 v2）：**

1. 按标准 ZIP 打开（首两字节 `PK`）；
2. 读根 `dspack.json`：缺失 / 非对象 → 不是 dspack → 拒载；
3. `format` ≠ `"dspack"` 或 `version` ≠ 3 → 报「不支持该 `.dspack` 版本」；
4. 通过 → 按 manifest `type` 分形态处理（§3）。

---

## 3. 归档内部布局（两种形态）

### 3.1 profile 形态（manifest v5 `type:"profile"`）

```
<name>-<version>.dspack
└── ZIP 内:
    ├── dspack.json            # ★ version 3
    ├── manifest.json          # ★ v5（type: profile）
    ├── package.json           # profile 机器文件（可选快照，被 manifest 权威重建）
    ├── pnpm-workspace.yaml    # 可选
    ├── pnpm-lock.yaml         # 可选
    ├── overrides/             # → $DSH_HOME/profiles/<name>/（profile 根）
    │   ├── cordis.patch.yml
    │   └── ...
    └── home/                  # → $DSH_HOME/（可选，上一级目录内容，见 §5）
        ├── skills/<name>/SKILL.md
        └── .agent-presets/<id>/agent.cordis.yml
```

### 3.2 dshhome 形态（manifest v5 `type:"dshhome"`）

```
<name>-<version>.dspack
└── ZIP 内:
    ├── dspack.json            # ★ version 3
    ├── manifest.json          # ★ v5（type: dshhome）
    ├── package.json           # 可选（defaultProfile 快照）
    ├── pnpm-workspace.yaml    # 可选
    ├── pnpm-lock.yaml         # 可选
    └── overrides/             # → $DSH_HOME/（home 根，按相对路径平铺）
        ├── AGENTS.md
        ├── profiles/<name>/cordis.patch.yml
        ├── .agent-presets/<id>/agent.cordis.yml
        ├── skills/<name>/SKILL.md
        └── data/...
```

> 关键约定：**ZIP 根必须包含 `dspack.json` 与 `manifest.json`**。用户内容进 `overrides/`（profile 形态）或 `overrides/` + `home/`（profile 形态带上一级目录）。

## 4. 归档内容清单

| 类别 | 文件 | 说明 |
| --- | --- | --- |
| 必有 | `dspack.json` | 容器标记（`format` / `version` 3） |
| 必有 | `manifest.json` | v5 契约头（`type` 决定形态） |
| 可选 | `package.json` / `pnpm-workspace.yaml` / `pnpm-lock.yaml` | 机器文件 / 设置 / 传递依赖锁定 |
| 必有（目录） | `overrides/` | 用户文件（落点随形态，见 §3） |
| 可选（目录） | `home/` | 仅 profile 形态：上一级目录内容（见 §5） |
| 不打包 | `node_modules` 等 | 依赖由 `pnpm install` 重建；重内容走 `files[]` / `skills[]` |

---

## 5. `home/` 目录（profile 形态的「上一级目录」）

`home/` 是**单 profile 整合包携带 home 级内容**的载体：

- `home/xxx` → 安装时写到 `$DSH_HOME/xxx`（**不是 profile 根**）；
- 例：`home/skills/<name>/SKILL.md`、`home/.agent-presets/<id>/agent.cordis.yml`、`home/AGENTS.md`；
- 语义与 `overrides/` 一致：**文件级复制替换**，不做字段级合并；
- 安全过滤同 `overrides/`（§8）。

> 为什么需要 `home/`：skill（`$DSH_HOME/skills`）、agent-preset（`$DSH_HOME/.agent-presets`）在 DSH 里是 **home 级**（profile 目录的上一级），不在单个 profile 目录内。`home/` 让 profile 整合包也能顺带分发这些全局单元，而不必升级成整个 dshhome 快照。

---

## 6. `overrides/` 语义

`overrides/` 是「随包携带、安装时写到目标根」的目录，落点随形态：

- **profile 形态**：`overrides/xxx` → `$DSH_HOME/profiles/<name>/xxx`；
- **dshhome 形态**：`overrides/xxx` → `$DSH_HOME/xxx`。

「覆盖」是文件级复制替换，不是语义合并；真正的「合并式覆盖」由 `cordis.patch.yml`（Cordis 补丁层）承担。

### dshhome 形态的四类单元落盘

| 单元 | `overrides/` 内 | 安装落点 | 依赖坐标层 |
| --- | --- | --- | --- |
| profile | `profiles/<name>/cordis.patch.yml` 等 | `$DSH_HOME/profiles/<name>/` | ✅ `dependencies`（manifest 权威重建） |
| preset | `.agent-presets/<id>/agent.cordis.yml` + `preset.yml` | `$DSH_HOME/.agent-presets/<id>/` | ❌ 纯文件 |
| skill | `skills/<name>/SKILL.md`（+ 资源） | `$DSH_HOME/skills/<name>/` | ❌ 纯文件（重技能走 `skills[]`） |
| 全局指令 | `AGENTS.md` | `$DSH_HOME/AGENTS.md` | ❌ 纯文件 |

---

## 7. files[] / skills[] 下载（重内容按需拉取）

- profile 形态：`files[]` 落 profile 根内；dshhome 形态：落 `$DSH_HOME` 内。
- 安装时逐个下载到 `path`，校验 `sha256` + `size`；任一失败 → 删除已下文件并整体回滚。
- 常规插件走 npm / git（`dependencies`），不进 `files[]` / `skills[]`。

---

## 8. 安全过滤（沿用 v1 四类规则 + 扩展）

`overrides/` / `home/` 内文件打包时沿用 v1 四类安全过滤，并新增 home 级排除：

| 新增排除（相对 `$DSH_HOME`） | 理由 |
| --- | --- |
| `.credentials.yaml` | 敏感凭据 |
| `.anonymous-user-id` | 运行时状态 |
| `attachments/` | 运行时数据 |
| `settings.yaml` | 全局设置默认排除 |
| `skills/.system/` | 安装内部系统技能（`skipSystem`） |
| `profiles/web/`、`profiles/headless/` | 安装基线 profile 模板（dshhome 形态） |
| `profiles/node_modules/` | 派生（v1 `node_modules` 规则已覆盖） |

---

## 9. 安装端行为

**profile 形态**：

1. 解 ZIP → 校验 `dspack.json`（v3）→ 读 manifest（v5、`type:"profile"`）；
2. `overrides/` 覆盖到 profile 根 → 安装 `dshVersion` → `pnpm install` → `reconcileProfile`；
3. `home/`（若有）覆盖到 `$DSH_HOME` 根；
4. `files[]` 下载 + 校验，失败回滚。

**dshhome 形态**：

1. 解 ZIP → 校验 `dspack.json`（v3）→ 读 manifest（v5、`type:"dshhome"`）；
2. 校验 `profiles` 非空、不含 `web` / `headless`，`defaultProfile` 存在；
3. **先确保 `dshVersion` 的 DSH 已安装**；
4. 建实例 `$DSH_HOME`；
5. **逐 profile**：`overrides/profiles/<name>/` 落盘 → `pnpm install` → `reconcileProfile`（各自独立）；
6. home 级 `overrides/` 其余内容落盘；
7. `files[]` / `skills[]` 下载 + 校验，失败回滚；
8. `defaultProfile` 设为默认。

---

## 10. 与 v1 / v2 的关系

| 版本 | 容器 | 覆盖目标 | 状态 |
| --- | --- | --- | --- |
| v1 | `.tgz` | 单 profile（扁平快照） | **现行**（`pack-structure/v1.md`） |
| v2 | `.dspack`（v2） | 单 profile（`overrides/` → profile 根） | 未来（`pack-structure/v2.md`，无 `home/`） |
| **v3** | `.dspack`（v3） | **profile（`overrides/` → profile 根 + 可选 `home/` → home 根）\|\| dshhome（`overrides/` → home 根）** | **未来**（本文） |

> v3 是 v2 的超集：profile 形态 = v2 + `home/`；dshhome 形态 = 覆盖目标提升到整个 home。索引与存储的「指针制」分工不随容器变化而改变。

---

## 11. 结论

> `.dspack` v3 = **纯 ZIP + 根 `dspack.json`（version 3）+ 两种形态**：`type:"profile"` 用 `overrides/`（profile 根）与可选 `home/`（上一级目录）承载单 profile 及其全局 skill/preset；`type:"dshhome"` 用 `overrides/` 按 `$DSH_HOME` 根平铺承载整个工作环境。标准 ZIP 保证可直接打开，根标记保证版本演进，`home/` 让「单 profile 也能带全局单元」、dshhome 让「整个 home 可还原」——在 v2 之上的平滑演进，模仿 mrpack 而不失 DSH 的层栈与 home 契约。
