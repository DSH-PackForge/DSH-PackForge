# 发布契约（publishing）· v1

> 状态：现行
> 依赖：`specs/manifest/v4.md`（兼容读 v3）、`specs/pack-structure/v2.md`（兼容 `.tgz`）、`specs/index/index.md`

本规范定义**一个整合包如何从「源码仓库」走到「被市场自动收录」**：仓库怎么建、怎么打主题标签、Release 怎么发、sha256 侧车怎么给，以及索引采集器（`dsh-pack-market/scripts/collect.mjs`）如何消费。端到端落地参考：`DSH-PackForge/all-about-whales`。

## 1. 目标

- **零人工登记**：作者只按本规范建仓 + 发 Release，采集器即可自动发现并收录，无需向任何地方提交 PR。
- **可复现、可校验**：进索引的下载三要素 = `downloadUrl` + `sha256` + `size`，安装端据此校验完整性。

## 2. 仓库创建规范

### 2.1 三个“必需”

1. **公开（public）**——采集器走 `raw.githubusercontent.com` 与 GitHub Release，私有仓库读不到，会被跳过。
2. **主题标签 `dsh-pack`**（About → Topics）——这是全网唯一的发现入口；没打就永远扫不到。
3. **根部放 `manifest.json`**——采集器只读**默认分支（`default_branch`）根**的 `manifest.json`，按 manifest v4 书写（旧 v3 亦兼容读取）。

### 2.2 命名与元数据

- 仓库名 = 包名 `<name>`（kebab-case），且与 `manifest.name` 一致，如 `all-about-whales`。
- About 的 `description` 建议填写（对人可读）；**`archived` 仓库会被采集器跳过**。

### 2.3 建议的仓库布局

```
<name>/
├── manifest.json          # 必须：manifest v4（根）
├── overrides/             # pack-structure v2 的用户文件（cordis.patch.yml 等）
├── README.md              # 推荐：作者说明 / 装了什么
├── package.json           # 可选：安装快照（manifest 为权威，可被重建）
├── pnpm-lock.yaml         # 可选：冻结的锁定文件
└── .github/workflows/…    # 可选：CI 自动打包 + 发版
```

## 3. Release 创建规范（默认下载来源）

### 3.1 打 tag

`v<manifest.version>`，如 `manifest.version = "1.0.0"` → tag `v1.0.0`。

### 3.2 上传资产

- **打包资产（单个）**：`<name>-<version>.dspack`（推荐，pack-structure v2）；过渡期兼容 `.tgz`。**同一 Release 内不要混放多个打包资产**——采集器按 `.dspack > .tgz > .zip` 的优先级只取一个，混放可能选中旧包。
- **sha256 侧车资产**：`<name>-<version>.dspack.sha256`（格式见 §4）。

### 3.3 硬约束

- Release 必须是**正式发布**（非 `draft`、非 `prerelease`），否则 `releases/latest` 取不到。
- 采集器固定读 **`releases/latest`**（最新正式发布）的资产集合。

## 4. sha256 侧车

- 文件名 = 打包资产名 + `.sha256`（如 `all-about-whales-1.0.0.dspack.sha256`）。
- 内容 = **64 位小写十六进制 sha256**，可带换行；采集器取 `trim` 后第一个空白分隔的 token。
- 用途 = **安装时**校验下载完整性（采集器只搬运、不校验）。
- 生成（Windows PowerShell）：

  ```powershell
  (Get-FileHash .\all-about-whales-1.0.0.dspack -Algorithm SHA256).Hash.ToLower()
  ```

## 5. downloadUrl 直链（可选，替代 Release）

若 manifest 中写了 `downloadUrl`（直接指向打包资产的 URL），采集器**跳过 §3 的 Release**，改走：

- `downloadUrl` 本体 + 读取 `<downloadUrl>.sha256` 侧车（URL 直接拼接 `.sha256`）；
- 体积取 `HEAD` 响应的 `content-length`。

适用裸链分发（如 raw / 对象存储/CDN）。否则请**省略 `downloadUrl`**，交给 Release 默认。

## 6. 收录流程（采集器如何消费）

1. `GET /search/repositories?q=topic:dsh-pack&per_page=100&sort=updated`，排除 `archived`；
2. 逐个读「默认分支根 `manifest.json`」，缺失/非法 → 跳过并告警；
3. `manifestVersion` 缺省按 4；`category` 缺省 `uncategorized`；
4. 组装下载三要素：`downloadUrl`（直链或 Release 资产）+ `sha256`（侧车）+ `size`，`updatedAt` 取 `updatedAt`/`published_at`/`pushed_at` 的较早可用值；
5. 平铺进 `index.json`（schemaVersion 1，字段见 `specs/index/index.md`），按 `updatedAt` 倒序。

## 7. 端到端示例（以 all-about-whales 为例）

```bash
# 1) 建仓 + 打主题标签
gh repo create DSH-PackForge/all-about-whales --public
gh repo edit DSH-PackForge/all-about-whales --add-topic dsh-pack

# 2) 打包（产出 .dspack）
node pack.mjs                    # → all-about-whales-1.0.0.dspack

# 3) 写 sha256 侧车
(Get-FileHash .\all-about-whales-1.0.0.dspack -Algorithm SHA256).Hash.ToLower() `
  | Out-File -Encoding ascii .\all-about-whales-1.0.0.dspack.sha256

# 4) 发正式 Release（挂 .dspack + .sha256 两个资产）
gh release create v1.0.0 \
  all-about-whales-1.0.0.dspack \
  all-about-whales-1.0.0.dspack.sha256 \
  --title "All About Whales v1.0.0"
```

## 8. 发布校验清单

- [ ] 仓库 `public`；About 已打 `dsh-pack`；
- [ ] 根 `manifest.json` 存在，`manifestVersion` / `type` / `version` 齐全；
- [ ] `overrides/` 含所需用户文件（按 pack-structure v2）；
- [ ] Release tag = `v<version>`（与 `manifest.version` 一致）；
- [ ] Release 为正式发布（非 draft / 非 prerelease）；
- [ ] 只有一个打包资产 `<name>-<version>.dspack`；
- [ ] 侧车 `<name>-<version>.dspack.sha256` 为 64 位小写 hex。
