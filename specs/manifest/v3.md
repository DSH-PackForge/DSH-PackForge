# Manifest v3 规格说明（历史）

> 状态：**历史（仍兼容导入）**。整合包 = 「可复现的层栈契约」：依赖坐标全部钉死为精确版本 / commit sha。v4（`../manifest/v4.md`）为其现行演进（新增 `type` + `files[]`），启动器/导入侧仍兼容导入 v3。
>
> 参考实现：`dsh-launcher/docs/PACK_MANIFEST.md`（启动器导入侧）。启动器同时兼容导入 manifestVersion 2。

---

## 1. 概述

v3 在 v2「三分离层栈契约」的基础上，把**可复现性**提升为硬约束：

- `dependencies` 从「pnpm 原始 spec 透传」改为「**坐标 → 固定版本**」：npm 包钉精确版本，git 包钉 commit sha；
- `dshVersion` 从 semver 范围改为**固定的精确版本号**（导出时所用的 DSH 版本），导入时直接安装该版本；
- `displayName` / `description` 升级为**多语言 map**，导入时按当前界面语言作为默认实例名。

---

## 2. 整合包结构

一个整合包是一个 `.tgz` 文件，压缩包**根目录**包含：

| 文件 | 必需 | 说明 |
| --- | --- | --- |
| `manifest.json` | ✅ | 整合包元数据与依赖坐标（本文档的主题） |
| `package.json` | ✅ | 可直接 `pnpm install` 的 profile 清单（由 `dependencies` 转换而来） |
| `cordis.patch.yml` | 否 | profile 的 patch 层；缺失时回退到 manifest 的 `patch` 字段 |
| `pnpm-lock.yaml` | 否 | 锁定传递依赖版本（导入时优先 `--frozen-lockfile`） |
| `pnpm-workspace.yaml` | 否 | profile 的 pnpm 设置（hoist、allowBuilds 等） |

---

## 3. 字段定义

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `manifestVersion` | number | ✅ | 固定为 `3` |
| `name` | string | ✅ | 整合包标识（kebab-case），也是 tgz 文件名前缀 |
| `version` | string | ✅ | 整合包自身版本号（semver） |
| `displayName` | string \| object | 否 | 显示名。字符串，或以语言代码为键的 map（如 `{"zh-CN": "...", "en-US": "..."}`）；导入时按当前界面语言作为默认实例名 |
| `description` | string \| object | 否 | 描述，形式同 `displayName` |
| `author` | string | 否 | 作者 |
| `icon` | string | 否 | 图标（URL 或相对路径，预留） |
| `dshVersion` | string | 否 | **固定的精确版本号**（如 `0.1.1-rc.2`），即导出该整合包时所用的 DSH 版本；导入时安装该版本。缺省时使用本机最新已装版本 |
| `profileName` | string | 否 | 导入时创建的 profile 名；缺省为 `pack`（保持 `web` profile 干净） |
| `bundles` | string[] | ✅ | profile 的 `dsh.profile.bundles` 层栈（按序挂载） |
| `dependencies` | object | ✅ | **坐标 → 固定版本**：npm 包为 `"包名": "精确版本"`；git 包为 `"github:owner/repo": "commit sha"`，monorepo 子目录用 `"github:owner/repo#path:/子目录"` |
| `patch` | string | 否 | `cordis.patch.yml` 的内联内容（与同名文件二选一，文件优先） |

## 5. dependencies 坐标转换

v3 的 `dependencies` 在导入时转换为 pnpm 可安装的 package.json 形式：

| manifest 形式 | 转换后 package.json |
| --- | --- |
| `"dsh-pet": "0.2.0"` | `"dsh-pet": "0.2.0"`（精确版本，原样保留） |
| `"github:owner/repo": "<sha>"` | `"repo": "github:owner/repo#<sha>"` |
| `"github:owner/repo#path:/pkg": "<sha>"` | `"pkg": "github:owner/repo#<sha>&path:pkg"` |

要点：

- **键是坐标、值是固定版本**，与 v2「键是包名、值是 pnpm spec」的语义相反；
- git 包转换后以仓库名 / 子目录名作为 package.json 依赖键；
- monorepo 子目录通过 `#path:/子目录`（manifest 侧）与 `#<sha>&path:pkg`（package.json 侧）表达。

## 6. 相对 v2 的变化

| 字段 | v2 行为 | v3 行为 |
| --- | --- | --- |
| `displayName` / `description` | 仅字符串 | 字符串或多语言 map（语言代码为键） |
| `dshVersion` | semver 范围（如 `>=0.1.0`）；导入时取其下限版本 | **固定的精确版本号**（如 `0.1.1-rc.2`）；导入时安装该版本 |
| `dependencies` | 值为 pnpm 原始 spec（`^0.2.0`、`git+https://github.com/owner/repo.git` 等），键为包名；导入时原样透传 | **坐标 → 固定版本**：npm 包钉精确版本，git 包（`github:` 坐标）钉 commit sha；导入时转换为 package.json 形式 |
| `patch` | 内联整文本 | 内联整文本；同时允许以独立 `cordis.patch.yml` 文件携带（文件优先） |
| 锁文件 | 未约定 | 可携带 `pnpm-lock.yaml`，导入时优先 `--frozen-lockfile` |
| pnpm 设置 | 未约定 | 可携带 `pnpm-workspace.yaml`（hoist、allowBuilds 等） |

> v2 是 [ModPack-CLI](https://github.com/DSH-PackForge/ModPack-CLI) 写出的原始格式，详见 `v2.md`。

---

## 7. 导入行为（启动器）

1. 读取 `manifest.json` 后弹出确认框：实例名（默认当前语言的 `displayName`）、profile 名（默认 `profileName`，缺省 `pack`）。
2. 为整合包新建实例与专属 DSH_HOME；`web` profile 保持纯净，整合包内容只进入 pack profile。
3. 安装 `dshVersion` 指定的 DSH 版本（未安装则自动下载；GitHub-only 标签走源码构建）。
4. 写入 `package.json` / `cordis.patch.yml` / `pnpm-lock.yaml` / `pnpm-workspace.yaml` 后执行 `pnpm install`（优先 `--frozen-lockfile`，失配时回退普通安装）。
5. pack profile 设为该实例的默认 profile。

---

## 8. 结论

> v3 的本质是把 v2 的「层栈契约」升级为「可复现的层栈契约」：依赖坐标钉死精确版本与 commit sha、`dshVersion` 钉死导出环境、可选锁文件兜住传递依赖，使同一个 `.tgz` 在任何机器上导入都能得到字节级一致的运行环境；同时通过多语言元数据与启动器实例化流程，让整合包成为可分发的完整产品单元。
