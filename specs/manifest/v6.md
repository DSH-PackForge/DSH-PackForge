# 清单规范 v6（manifest v6，现行）

> 状态：**现行**。新生成的整合包统一采用 `manifestVersion: 6` 与容器版本 `dspack.json.version: 4`。
>
> 关联：[清单 v5（历史）](v5.md) · [容器规范 v4](../pack-structure/v4.md) · [插件数据与可选资源规范 v1](../dsh_pack/v1.md) · [启动器注册表](../launcher-registry.md)

v6 在延续 v5 基础结构的同时，新增三项核心能力：为每个配置档（profile）记录插件的多语言展示信息与精确 npm 包源（registry），为可选配置、技能与插件数据建立独立资源清单，并要求安装端保存可用于后续更新的安装基线（baseline）。

## 1. 形态与字段

`manifest.json` 位于归档根目录，采用 UTF-8 编码的 JSON 格式。`name` 与整合包自身的 `version` 为必填项，生成端必须显式写入 `type`：

- **`"profile"`（单配置档）**：描述单个安装目标配置档。
- **`"dshhome"`（全局目录，即整个 `DSH_HOME`）**：描述一组配置档及其共享的 `DSH_HOME` 级资源。

| 字段 | 适用位置 | 说明 |
| --- | --- | --- |
| `displayName`、`description`、`author`、`icon` | 整合包根 | 整合包显示名称、简介、作者与图标 |
| `dshVersion`、`dshVersions`、`launchers` | 整合包根 | 首选 DSH 版本、实测兼容版本集合、启动器兼容声明 |
| `bundles`、`dependencies`、`patch` | 单配置档根或 `profiles[名称]` | 有序插件层栈、依赖坐标与该配置档的基础 Cordis 补丁 |
| `plugins` | 单配置档根或 `profiles[名称]` | 以插件 ID 为键的可选展示信息与专用 npm 源声明 |
| `defaultProfile`、`profiles`、`presets`、`instructions` | `dshhome` 根 | 默认配置档、至少一个具名配置档、预设与全局指令 |
| `files`、`vendored` | 整合包根 | 带大小和 SHA-256 的下载指针、随包分发的依赖副本 |

说明：
- `profileName` 指定单配置档的默认安装名称。
- `dshhome` 形态的 `defaultProfile` 必须指向本包 `profiles` 中已声明的配置档；`web` 与 `headless` 属于 DSH 系统保留配置档，不得占用。
- v5 中定义的依赖坐标、层栈顺序、启动器兼容声明与 `files[]` 下载指针继续适用；v6 中按勾选导出的技能改由根目录 `skill.json` 描述。

## 2. 插件展示信息

`plugins` 为对象结构，键名必须对应所属配置档的 `bundles` 或 `dependencies`；同一插件可在不同配置档中分别配置展示信息与包源。界面展示时以 `name` 和 `desc` 为主，同时保留原始插件 ID 以便定位。读取旧版整合包或缺失展示字段时，回退使用插件原本的包名与简介。

| 字段 | 类型 | 生成规则 |
| --- | --- | --- |
| `name` | 字符串或语言映射（locale map） | 依次取：作者输入 → 插件 `locale/*.json` 中的 `meta.title` → `package.json.name` → 插件 ID |
| `desc` | 字符串或语言映射，可省略 | 依次取：作者输入 → 各语言的 `meta.description` → `package.json.description` |
| `icon` | HTTPS URL 或归档内相对路径，可省略 | 读取插件 `exports["./icon"]` 或顶层 `icon`，也可由作者手动指定 |
| `source` | 对象，可省略 | 该精确版本对应的专用 npm 包源（registry），规则见下节 |

### 语言文件与图标规则

- **语言文件读取**：优先读取插件显式导出的 `./locale/<语言>.json` 或 `./locale/*.json`（支持通过导出表映射到自定义目录）；若未配置 `exports`，则读取包根目录下的 `locale/` 目录。界面优先匹配当前系统语言，并按「英文 → 中文 → 首个可用翻译」顺序回退。
- **公共图标 CDN**：已确认公开发布的 npm 插件，其图标可使用固定版本的 `https://cdn.jsdelivr.com/npm/<包名>@<精确版本>/<文件路径>`；PackForge 界面加载失败时会尝试 `cdn.jsdelivr.net` 上的相同 npm 路径。
- **内嵌图标与安全限制**：私有包、Git 依赖或本地依赖的图标可嵌入归档内的 `assets/plugins/` 目录，严禁使用来源不明的私有包名向公共 CDN 发起探测请求。归档内嵌图标支持自包含（无外链）的 SVG、PNG、JPEG 与 WebP 格式，单文件大小上限为 256 KiB。

## 3. 精确 npm 包源（registry）

`source` 的格式为 `{"type":"npm","registry":"https://registry.example/npm/"}`。该声明**仅**对同一配置档 `dependencies[id]` 中指定的精确 npm 版本生效：

- 例如，为 `@example/foo@1.2.3` 声明的 `source`，对 `@example/bar`、`@example/foo@1.2.4`、其他配置档中的同名插件以及该插件未声明的传递依赖均不生效。
- 版本范围、包别名、Git 依赖与 `file:` 本地引用均不得声明 npm 包源。插件升级版本后若仍需使用专用源，必须在新版清单中为新版本号重新声明。

### 生成与认证规范

- **来源预填**：生成端允许作者选择包源，但仅能基于「包名与精确版本号均可核对」的本地记录预填，严禁根据 scope 或同名旧版本的记录推断包源。
- **URL 与凭据隔离**：`registry` 接受 HTTP 或 HTTPS 服务地址（可带路径），但不得包含内嵌用户名、密码、查询参数或锚点（fragment）。认证仅在安装目标机本地完成，按 URL 路径匹配凭据；目标配置档的本地 npm 配置在同路径下优先于用户全局配置。归档内不得携带任何认证信息，且明文 HTTP 请求及未经授权的重定向不得携带敏感请求头。

### 安装与校验规范

- 安装或更新时，从指定包源读取该精确版本的元数据，按 `dist.tarball` 下载包体，并严格校验 `dist.integrity` 与压缩包内 `package/package.json` 的 `name`、`version`。
- 本地缓存、锁文件记录地址以及 `vendored` 副本仅可作为「可核验同一原件」的来源；参考实现会先向指定包源核验，失败即报错并中止安装；若同时存在内嵌副本，还须比对实际字节与声明摘要。
- 严禁因指定包源失败而回退到公共源、修改用户全局 registry，或为整个 scope 统一改源。客户端应持久化记录已验证的直接依赖及其来源，以便后续重装或再次导出时完整复现。

## 4. 可选资源、安装与兼容性

- **展示摘要 `resources`**：`resources` 为可选的纯展示摘要，可同时出现在归档内清单与用于发布的仓库根 `manifest.json` 中。键名限定为 `path.json`、`provider.json`、`mcp.json` 与 `skill.json`，对应值为条目摘要数组。摘要条目仅保留 `id`、`name`、`desc`、`scope`、`ref`、`commit`（`path.json` 条目可额外保留 `plugin` 以区分不同插件各自编号的路径规则），空值字段可省略。凭据引用、模型服务商或 MCP 的具体配置、命令参数与文件内容**均不得**写入摘要。
- **归档内资源清单**：用户勾选导出的可选资源存储在归档根目录的 `path.json`、`provider.json`、`mcp.json` 与 `skill.json` 中。安装端须逐条展示名称、作用域（scope）、目标路径及缺失的凭据，导出器与市场仅发布凭据引用名。扩展文件布局、冲突处理、凭据填写与更新基线规则分别见[插件数据与可选资源规范 v1](../dsh_pack/v1.md)与[容器规范 v4](../pack-structure/v4.md)。
- **向后兼容**：新版读取器继续按原始声明解析 manifest v4/v5 格式的 `.dspack`，不得将 v6 清单简单降标为 v5。市场索引继续沿用 `schemaVersion: 2`，完整的插件展示资料保留在按需加载的 `manifest.json` 中。可对照[单配置档示例](../../examples/v6/profile/manifest.json)与[全局目录示例](../../examples/v6/dshhome/manifest.json)进行校验。
