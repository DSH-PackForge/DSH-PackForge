# Manifest v6 规范（现行）

新整合包使用 `manifestVersion: 6` 与 `dspack.json.version: 4`。v6 为每个 profile 记录插件的多语言展示资料和精确 npm 来源，为可选配置、技能和插件数据定义独立清单，并要求安装端保存可用于更新的基线。

## 1. 形态和字段

`manifest.json` 位于归档根，采用 UTF-8 JSON。`name` 和整合包自身的 `version` 必填。生成端必须写入 `type`。`profile` 包描述一个安装目标，`dshhome` 包描述一组 profile 及其共享的 DSH_HOME 资源。

| 字段 | 适用位置 | 含义 |
| --- | --- | --- |
| `displayName`、`description`、`author`、`icon` | 整合包根 | 整合包名称、简介、作者与图标 |
| `dshVersion`、`dshVersions`、`launchers` | 整合包根 | DSH 首选版本、兼容版本集、启动器兼容声明 |
| `bundles`、`dependencies`、`patch` | 单 profile 根或 `profiles[名称]` | 有序插件层、依赖坐标与该 profile 的基础 Cordis 补丁 |
| `plugins` | 单 profile 根或 `profiles[名称]` | 以插件 ID 为键的可选展示与专用源声明 |
| `defaultProfile`、`profiles`、`presets`、`instructions` | `dshhome` 根 | 默认 profile、至少一个具名 profile、预设与全局指令 |
| `files`、`vendored` | 整合包根 | 带大小和 SHA-256 的下载指针、随包分发的依赖副本 |

`profileName` 指定单 profile 的默认安装名。`dshhome` 的 `defaultProfile` 必须指向本包声明的 profile；`web` 与 `headless` 属于 DSH 安装基线。v5 定义的依赖坐标、层顺序、启动器兼容声明与文件指针继续适用。v6 导出按选择写入的技能以根 `skill.json` 表达。[基础字段和版本语义](v5.md) · [启动器注册表](../launcher-registry.md)

## 2. 插件展示资料

`plugins` 是对象。每个键必须对应本 profile 的 `bundles` 或 `dependencies`；同一插件允许在不同 profile 中设置不同展示值和来源。界面以 `name` 和 `desc` 显示插件，同时保留原始 ID 供定位。读取旧包或缺少展示值时，使用已有包名与简介。

| 字段 | 类型 | 生成规则 |
| --- | --- | --- |
| `name` | 字符串或语言映射 | 优先作者输入，然后是插件导出的 `locale/*.json` 中的 `meta.title`，随后使用 `package.json.name` 或插件 ID |
| `desc` | 字符串或语言映射，可省略 | 优先作者输入，然后是各语言的 `meta.description`，然后是 `package.json.description` |
| `icon` | HTTPS URL 或归档内相对路径，可省略 | 读取插件 `exports["./icon"]` 或顶层 `icon`，也可由作者指定 |
| `source` | 对象，可省略 | 精确版本对应的 npm registry，字段见下节 |

locale 读取包显式导出的 `./locale/<语言>.json` 或 `./locale/*.json`，允许导出表映射到自定义目录。没有 exports 时按包根的 locale 目录读取语言文件。界面优先使用当前语言，可回退到英文、中文、首个可用翻译。公开 npm 插件的图标使用固定版本的 `https://cdn.jsdelivr.com/npm/<包名>@<精确版本>/<文件路径>`。PackForge 界面加载失败时会尝试 jsDelivr 的 `cdn.jsdelivr.net` 同路径。只有已确认公开分发时才可生成该 URL。私有、Git、本地依赖的图标可以嵌入 `assets/plugins/`；禁止用不明来源的私有包名探测公共 CDN。归档图标支持自包含 SVG、PNG、JPEG、WebP，单文件最多 256 KiB。

## 3. 精确 npm 来源

`source` 的格式为 `{"type":"npm","registry":"https://registry.example/npm/"}`。声明仅对同一 profile 的 `dependencies[id]` 指定的精确 npm 版本生效。例如，`@example/foo@1.2.3` 的声明对 `@example/bar`、`@example/foo@1.2.4`、其他 profile 的同名包及该插件的未声明传递依赖均无影响。版本范围、别名、Git 和 `file:` 引用不得声明 npm 来源。升级后如需专用源，必须在新版清单中声明新的精确版本。

生成端允许作者选源，仅以能核对包名及精确版本的记录预填；禁止从 scope 或同名旧版推断来源。registry 允许 HTTP(S) 服务或带路径的服务，禁止内嵌用户名、密码、查询参数或片段。认证只在目标机完成。按 URL 路径匹配凭据，目标 profile 的本机 npm 配置对相同路径优先于用户配置；归档中的文件不能提供认证信息，HTTP 和未经授权的重定向不携带敏感头。

安装或更新时从指定源读取精确版本的元数据，按 `dist.tarball` 取件，校验 `dist.integrity` 和压缩包内 `package/package.json` 的 `name`、`version`。本地缓存、锁文件地址和 `vendored` 只能提供可核验的同一原件。参考实现先向指定源验证，失败时报告坐标并停止；同时存在内嵌副本时还要对比实际字节和声明摘要。禁止回退到公共源、修改用户全局 registry 或为整个 scope 改源。客户端应持久化已验证的直接依赖与来源，使后续重装及再导出能够重现该坐标。

## 4. 附件、安装与兼容

`resources` 为可选的纯展示摘要，可同时出现在归档内和用于发布的根 manifest。键限定为 `path.json`、`provider.json`、`mcp.json`、`skill.json`，每个值是摘要数组。条目仅取 `id`、`name`、`desc`、`scope`、`ref`、`commit`；`path.json` 条目还可记录 `plugin`，以区分插件各自编号的路径规则。没有值的字段可省略。凭据引用、Provider/MCP 配置、命令与文件内容不进入摘要。

可选附件使用归档根的 `path.json`、`provider.json`、`mcp.json`、`skill.json`。安装端须按条目列出名称、作用域、目标与缺少的凭据。导出器和市场仅发布引用名。扩展文件、冲突选择、凭据填写和更新基线分别见[插件资源规范](../dsh_pack/v1.md)与[容器 v4](../pack-structure/v4.md)。

新版读取器继续按原声明解析 manifest v4/v5 的 `.dspack`。禁止把 v6 简单降标为 v5。市场索引继续使用 `schemaVersion: 2`，完整插件资料留在按需加载的 manifest。可对照[单 profile 示例](../../examples/v6/profile/manifest.json)和[整机示例](../../examples/v6/dshhome/manifest.json)。
