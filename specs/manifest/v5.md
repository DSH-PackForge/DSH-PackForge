# Manifest v5 规格说明（现行 · v5 r3）

> 状态：**现行（v5 r3）**。r2 = 2026-09 修订：vendored 依赖内嵌（`vendored{}`，§12）、dsh 版本兼容集（`dshVersions`，§13）、启动器兼容声明（`launchers`，§14）。**r3 = 2026-09 修订（实测驱动）**：依赖键分两类（裸坐标 = 只从网络 / `vendor:<包名>` = 只从包内，§2）、关联锁文件的**本地化安装算法**（§11、`../pack-structure/v3.md` §8.3）、闭包条目键改 `name@version` 并增 `kind`/`name`（§12）、版本后缀约定撤销为可选（§12）。配套 RFC：`rfc-vendored-payload-and-offline-packs.md`、`rfc-dsh-version-set-and-launcher-compat.md`（平台工作区）。v5 是**统一版本**：`type` 分 `"profile"`（单 profile）与 `"dshhome"`（整个 DSH_HOME）两种形态，配合 `.dspack` v3 容器（见 `../pack-structure/v3.md`）承载。生成侧 `dsh-packforge-app` 与参考实现 `all-about-whales` 均以 v5 产出，导入侧兼容 v4 / v3。`manifestVersion` 字段恒为 `5`——r1 / r2 / r3 包同号，r2 与 r3 均为严格超集（r1 的一切规则原样有效，仅新增可选字段与更明确的键语义）。
>
> 关联：`../manifest/v4.md`（v5 的 `profile` 形态即 v4 单 profile 契约，历史）、`../pack-structure/v3.md`（承载 v5 的容器，两种形态 + `home/` 目录）、`../index/index.md`（市场索引可跟进 `type` / `defaultProfile` / `presets` / `skills`）。

---

## 1. 概述

v5 保持 v4 的全部硬约束（依赖坐标钉死精确版本 / commit sha、`dshVersion` 精确、`displayName` / `description` 多语言、`files[]` 指针），并用 `type` 统一两种形态：

- **`type: "profile"`**：单 profile 整合包（即 v4 契约），一个 `bundles` + `dependencies` + `patch`。
- **`type: "dshhome"`**：整个 DSH_HOME 快照，多 profile + 全局 preset / skill / 指令。

`"collection"` 仍预留、校验器拒绝。

### 1.1 范围锁定（硬约束，仅 dshhome 形态）

dshhome 形态 = **`$DSH_HOME`（`~/.dsh`）的完整快照**：

- **明确排除 `~/.agents`（`DSH_AGENTS_HOME`）**——另一个共享 agent 配置根。
- **明确排除项目级内容**——项目根下的 `.dsh/`、`.agents/`、`AGENTS.md` / `CLAUDE.md` 跟随 cwd，不随包分发。

## 2. 字段定义（统一）

| 字段 | 类型 | 必需 | 形态 | 说明 |
| --- | --- | --- | --- | --- |
| `manifestVersion` | number | ✅ | 通用 | 固定为 `5` |
| `type` | string | ✅ | 通用 | `"profile"` 或 `"dshhome"`；`"collection"` 预留（校验器拒绝） |
| `name` | string | ✅ | 通用 | 整合包标识（kebab-case），也是 `.dspack` 文件名前缀 |
| `version` | string | ✅ | 通用 | 整合包自身版本号（semver） |
| `displayName` | string \| object | 否 | 通用 | 字符串或多语言 map |
| `description` | string \| object | 否 | 通用 | 同 `displayName` |
| `author` | string | 否 | 通用 | 作者 |
| `icon` | string | 否 | 通用 | 图标（URL 或归档内相对路径） |
| `dshVersion` | string | 否 | 通用 | **固定精确版本号**；缺省用本机最新已装版本 |
| `files` | array | 否 | 通用 | 重内容下载清单（`path + sha256 + size + urls[]`） |
| `dshVersions` | string[] | 否 | 通用 | 实测兼容的 DSH 版本枚举集（r2，§13）；缺省视同 `[dshVersion]` |
| `vendored` | object | 否 | 通用 | 坐标 → VendoredEntry，`vendor/` 内嵌依赖清单（r2，§12） |
| `launchers` | object | 否 | 通用 | 启动器 ID → 兼容声明（r2，§14） |
| `profileName` | string | 否 | profile | 导入时创建的 profile 名；缺省 `pack` |
| `bundles` | string[] | ✅ | profile | profile 层栈（`dsh.profile.bundles`，按序挂载） |
| `dependencies` | object | ✅ | profile | 两类键：`<裸坐标>`（只从网络）/ `vendor:<包名>`（只从包内）→ 固定版本（npm 精确版本 / git commit sha / 包内条目为包版本） |
| `patch` | string | 否 | profile | patch 层；或由 `overrides/cordis.patch.yml` 携带（文件优先） |
| `defaultProfile` | string | ✅ | dshhome | 指向 `profiles` 的某 key，导入后设为默认启动 profile |
| `profiles` | object | ✅ | dshhome | `name → ProfileUnit`（见 §4），至少 1 个，**不得含 `web` / `headless`** |
| `presets` | object | 否 | dshhome | `name → PresetUnit`（见 §5） |
| `skills` | array | 否 | dshhome | `SkillRef[]`（见 §6，可选索引） |
| `instructions` | string | 否 | dshhome | 全局指令文件相对路径，缺省 `AGENTS.md`（见 §7） |

> **前向兼容规则（v5 r2 成文）**：消费者必须忽略 manifest 中不认识的字段；规范的增量演进只新增可选字段，不改既有字段的类型与语义。`dependencies` 的值必须是精确版本 / commit sha——vendoring 不通过修改值表达（见 §12）。

> **依赖键的两类（r3）**：`<裸坐标>` = **只从网络**（npm 版本 / `github:owner/repo` + commit sha）；`vendor:<包名>` = **只从包内副本**（`vendored{}` 必有对应条目，装机时不为它联网；值 = 包的精确版本）。剥去**一次**前导 `vendor:` 后余下即**包名**（内嵌条目不记来源）。两类可在同一包内并存；同一包名不得同时以两类出现（冲突 → 拒装）。

> **坐标 → `package.json` 转换（安装端义务；v3 §5 的规则在 v5 恢复成文）**：`dependencies` 是「坐标 → 固定版本」，**不能原样写进 `package.json`**——pnpm 拒绝含 `:` 的依赖名（实测 `ERR_PNPM_INVALID_DEPENDENCY_NAME`）。安装端必须翻译：

| manifest 形式 | 转换后的 `package.json` |
| --- | --- |
| `"dsh-pet": "0.2.0"` | `"dsh-pet": "0.2.0"`（精确版本原样） |
| `"github:owner/repo": "<sha>"` | `"repo": "github:owner/repo#<sha>"`（**键取仓库名**） |
| `"github:owner/repo#path:/pkg": "<sha>"` | `"pkg": "github:owner/repo#<sha>&path:pkg"`（**键取子目录名**） |

> 命中 `vendored` 的**直接依赖**不走上表：键改取 **tarball 内 `package.json` 的 `name`**（权威），值写 `file:` 本地引用（见 §12、`../pack-structure/v3.md` §8.3）。依赖键名必须与 `bundles` 中该包的名字一致。

## 3. profile 形态（`type: "profile"`）

单 profile 整合包 = v4 契约：`bundles` + `dependencies` + `patch`，另加 `profileName`。`files[]` 落点在 profile 根内。

```json
{
  "manifestVersion": 5,
  "type": "profile",
  "name": "all-about-whales",
  "version": "1.0.0",
  "dshVersion": "0.1.1-rc.2",
  "profileName": "all-about-whales",
  "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "dafy-whale-theme", "dsh-pet"],
  "dependencies": {
    "dsh-pet": "0.2.0",
    "github:DViridescent/dafy-whale-theme": "99e8c57"
  }
}
```

> profile 形态可通过 `home/` 目录携带「上一级目录」内容（全局 skill / preset），见 `../pack-structure/v3.md` §5；这部分是容器层语义，不进入 manifest 字段。

---

## 4. ProfileUnit（dshhome 形态的 `profiles` 值）

`profiles` 的每个值就是「v4 单 profile 契约**去掉 `profileName`**」：

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `bundles` | string[] | ✅ | profile 层栈 |
| `dependencies` | object | ✅ | 坐标 → 固定版本 |
| `patch` | string | 否 | patch 层；或由 `overrides/profiles/<name>/cordis.patch.yml` 携带 |

> `profiles` **只含用户自定义 profile**；`web` / `headless` 是 DSH 安装自带模板（`PROFILE_TEMPLATES`），由 `dshVersion` 决定、不进包，校验器拒绝。

---

## 5. PresetUnit（纯文件单元）

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `path` | string | ✅ | 落在 home 的相对路径，缺省 `.agent-presets/<name>` |
| `description` | string | 否 | 展示用（预设自身 `preset.yml` 另有 name/description/order） |

> preset 物理格式 `.agent-presets/<id>/`：`agent.cordis.yml` + 可选 `preset.yml`。**插件依赖由安装 harness 解析**（`.` 相对 preset 目录、bare 包名从 harness base），preset 目录不带坐标层。

---

## 6. SkillRef（轻索引，元数据不重复）

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `path` | string | ✅ | 落在 `$DSH_HOME` 的相对路径，通常 `skills/<name>` |
| `sha256` | string | 否 | 仅重技能填 |
| `size` | number | 否 | 仅重技能填 |
| `urls` | string[] | 否 | 仅重技能填 |

> 小技能直接进 `overrides/skills/<name>/`，条目只记 `path`；重技能才带指针。skill 的 frontmatter 契约（`name`/`description`/`whenToUse`/invocation）由 DSH 定义，不在此冗余。

---

## 7. 全局指令（`instructions`）

`$DSH_HOME` 根的 Markdown 文件，缺省 `AGENTS.md`（`dsh-agent-instructions` 的 `USER_GLOBAL_FILE`）。作为 `overrides/AGENTS.md` 进包。保留字段让市场页/索引显式知道「带了全局指令」。

---

## 8. files[]（重内容，通用）

沿用 v4：`path + sha256 + size + urls[]`。profile 形态落 profile 根内，dshhome 形态落 `$DSH_HOME` 内。常规插件仍走 `dependencies`，不进 `files[]`；上游消失 / 从未发布 / 离线场景的依赖内嵌走 `vendored{}` + `vendor/`（§12），同样不进 `files[]`。

## 9. dshhome 完整示例

```json
{
  "manifestVersion": 5,
  "type": "dshhome",
  "name": "whale-studio",
  "version": "1.0.0",
  "displayName": { "zh-CN": "大肥鱼工作室", "en-US": "Whale Studio" },
  "dshVersion": "0.1.1-rc.2",
  "defaultProfile": "whale",
  "profiles": {
    "whale": {
      "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "dafy-whale-theme", "dsh-pet"],

  "instructions": "AGENTS.md"
}
```

## 11. 导入行为（启动器，目标）

> 与 `../pack-structure/v3.md` §10 的分工：本文定义 **manifest 驱动的完整导入流程**（阶段划分与失败语义），容器侧细节（解压、落点、`vendor/` 布局）见 v3。

导入分四个阶段；**任一阶段失败 → 整体回滚**（删除本次新建/覆盖的全部内容，恢复导入前状态——硬要求，不允许半装状态）。

### 11.1 阶段 0：识别与预检（未动任何文件）

1. **容器识别**：标准 ZIP → 根 `dspack.json`（`format` / `version`）→ 读 `manifest.json`；manifest 校验（`manifestVersion === 5`，导入侧兼容 v4 / v3），按 `type` 分形态；dshhome 另校验 `profiles` 非空、不含 `web` / `headless`、`defaultProfile` 指向存在的 key。
2. **launchers 判定（r2）**：条目归一化 → 判定表（`../pack-structure/v3.md` §8.4）→ 不满足时**警告放行**：须展示 `reason`、须用户确认、须日志留痕。
3. **dsh 版本决策**：`dshVersions`（r2）与已装求交 → **选定唯一版本**（命中多个：`dshVersion` 优先，其次集合内最新）；无交集 → 按 `dshVersion` 提示安装（可经用户确认自动安装）；两字段全缺省 → 用最新已装。
4. **vendored 预检（r2）**：`vendored{}` 的键必须 ∈ `dependencies` 且带 `vendor:` 前缀（**闭包条目**例外，键 = `name@version`，见 §12）；裸键出现在 `vendored{}` 即拒装（来源冲突）；`vendor/` 逐 tarball `sha256` + `size` 预验，并用现算 sha512 覆盖 lockfile 的 `integrity`——**装前发现损坏优于装到一半发现**。
5. **目标冲突检测**：profile 形态——同名 profile 已存在 → 明示将覆盖哪些路径，经确认继续；dshhome 形态——明示将覆盖 `$DSH_HOME` 的哪些内容，经确认继续。

### 11.2 阶段 1：落盘

- **manifest 权威重建**：按 manifest 重写目标 profile 的 `package.json`（`bundles` + `dependencies`；包内 `package.json` 快照被覆盖），逐键处理：**裸坐标**按 §2 转换表落来源 spec；**`vendor:` 键**剥前缀得包名 → 读该 tarball 内 `package.json` 核对 `name` / `version` → 按 lockfile 节点的形态本地化（两支见 `../pack-structure/v3.md` §8.3：npm 来源写 `file:` 并同步改 lockfile 的 importer / packages / snapshots；git 来源的 spec 从 lockfile importer 复制、只改 `resolution.tarball`）。键名与 `bundles` 条目一致。
- **profile 形态**：`overrides/` → profile 根；可选 `home/` → `$DSH_HOME` 根。
- **dshhome 形态**：`overrides/` → `$DSH_HOME` 按相对路径平铺（先逐 profile 落 `profiles/<name>/`，再落 home 级内容）。
- 落盘一律施加**路径穿越校验**（拒绝 `..` 越界）。

### 11.3 阶段 2：运行时与依赖

1. **确保阶段 0 选定的 DSH 版本已安装**；
2. **依赖安装**：`vendor/` 存在 → 按 §12 与 `../pack-structure/v3.md` §8.3 本地化（**npm 来源**：`package.json` 写 `file:` 且 lockfile 的 importer / packages / snapshots 同步改；**git 来源**：spec 从 lockfile importer 复制、只改 `resolution.tarball`，保留 `gitHosted`；**闭包条目**：只改 `resolution.tarball`）→ `pnpm install --frozen-lockfile --trust-lockfile`。**不用 `--prefer-offline`**——每个坐标只有一个来源，不存在「本地优先、否则联网」；**全部直接依赖都带前缀**时可加 `--offline` 作零网络断言。无 `vendor/` → `pnpm install`（建议 `--frozen-lockfile` 优先，遇 lockfile 错误码重试 `--no-frozen-lockfile`）；
3. **层栈对账（reconcileProfile）**：`bundles` 中同时是依赖的包，装完必须存在 bundle 声明；缺失 → 失败回滚。

### 11.4 阶段 3：重内容与收尾

1. `files[]` / `skills[]` 逐项下载 → `sha256` + `size` 校验；任一失败 → 清理已下文件 + 整体回滚；
2. dshhome 形态：`defaultProfile` 设为默认启动 profile；
3. **安装留痕**：选定 DSH 版本、launchers 警告与用户确认、vendored 回退是否发生——写入安装日志。

### 11.5 老启动器（不识 r2 / r3 字段）

按 r1 流程执行（读 `dshVersion`、纯网络 `pnpm install`）；遇死上游依赖 → 干净失败 + 回滚（受众声明指引见 `../publishing/v1.md` §8）；遇 `vendor:` 键 → pnpm 判非法包名 → **响亮失败（预期行为，记入兼容矩阵）**——需同时服务老启动器的包应另发不含前缀的版本。**不得因存在未知字段而拒装**（§2 前向兼容规则）。

### 11.6 启动器自选策略（不影响包格式）

home 隔离方式（如为整合包分配独立 home）、导入后的凭据/设置补种（凭据永不进包，由启动器从本机 home 补种）、skills 落点微调等由启动器自定；规范只约束「按上述阶段与回滚语义完成安装」。

## 12. vendored 依赖内嵌（v5 r2 · r3 重定义键语义与安装算法）

> 关联：`../pack-structure/v3.md` §8（`vendor/` 目录布局与统一安装算法）、`rfc-vendored-payload-and-offline-packs.md`、需求来源：[DSH-PackForge/DSH-PackForge#3](https://github.com/DSH-PackForge/DSH-PackForge/issues/3)。

与 r1 相比 `dependencies` 的**值**语义不变（精确版本 / commit sha），**键**新增 `vendor:<包名>` 一类（见 §2）：带前缀 = 只从包内副本，裸键 = 只从网络——**每个坐标的来源由键唯一确定，不存在「看情况」的兜底**。前缀键对不识 r2 的安装器是非法包名 → 响亮失败（预期行为）；裸键行为与 r1 完全一致。**内嵌条目不在键上记来源**（不写 `owner/repo`、不写 commit sha）。

**VendoredEntry**（`vendored` 的值）：

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `version` | string | ✅ | 与 `dependencies` 中该键的值一致（闭包条目 = lockfile 解析出的精确版本） |
| `kind` | string | 否 | `"direct"`（缺省）/ `"closure"`（闭包条目） |
| `name` | string | 闭包必填 | npm 包名；直接依赖可省（其包名即去前缀后的键） |
| `sha256` | string | ✅ | tarball 的 64 位十六进制哈希 |
| `size` | number | ✅ | tarball 字节数 |
| `path` | string | ✅ | ZIP 内相对路径（如 `vendor/npm__dsh-pet/dsh-pet-0.2.0.tgz`） |
| `reason` | string | 否 | `"upstream-missing"`（上游已消失）/ `"unpublished"`（从未发布上游）/ `"local-modified"`（本地修改版，如魔改插件——哈希为包内实际内容，与上游不一致是**有意的**）/ `"explicit"`（作者显式内嵌） |

**约束**：

1. `vendored` 的键必须 ∈ `dependencies`（profile 形态）或某 profile 的 `dependencies`（dshhome 形态，坐标去重后只存一份——`vendor/` 是包级，不分 profile）**且带 `vendor:` 前缀**；**裸键不得出现在 `vendored`**（来源冲突，拒装）。**闭包条目**例外：键 = `name@version`（`kind: "closure"`、`name` 必填），须能在随包 `pnpm-lock.yaml` 的 `packages:` / `snapshots:` 中找到——**反查 lockfile 是防夹带的安全约束**（闭包条目不是直接依赖，最易夹带）；
2. **来源由键决定，无覆盖旋钮**：`vendor:` 键从包内取（不联网），裸键从网络取，二者可在同一包内并存。打包端「全量收集」= 给全部直接依赖加前缀并沿 lockfile 收齐闭包（此时整包不再需要网络，安装端可加 `--offline`）；
3. **范围边界**：DSH 本体（`dshVersion` 对应的运行时）不内嵌，「先确保 DSH 已安装」前置条件不变；
4. **版本后缀改为可选**：`vendor:` 前缀已承担「只认包内 + 老启动器响亮失败」，魔改依赖可沿用上游版本号（`"vendor:dsh-pet": "0.3.0"` 是诚实写法）；作者可用 prerelease 后缀自行标记本地构建，规范不强制。**强制**的是三处一致（manifest `dependencies` 值 / `vendored[].version` / tarball 内 version，且禁止 `+` build metadata——npm 匹配会忽略其后缀）与**安装端禁止改写包内任何字节**（改写即破坏 `vendored.sha256` 完整性）。打包端须重算并覆盖 lockfile 的 `integrity`（见 `../pack-structure/v3.md` §8.6）。

**形态速查（按键的两类分布）**：

| manifest 形态 | 效果 |
| --- | --- |
| 全部直接依赖带前缀 + 闭包收齐 | 离线可装（零网络，安装端可加 `--offline`）；老启动器整包装不上 |
| 部分带前缀 | 前缀项只认包内（死上游 / 魔改由副本顶上），其余走网络；老启动器在前缀项上响亮失败 |
| 全裸键、无 `vendored` | 与 r1 完全一致 |

> 选型指引、完整示例与常见误区见 `../../docs/vendoring-guide.md`。
>
> **已评估的替代方案**：「`dependencies` 值改用 `file:` 相对路径」已被否决——`file:` 只能指向直接依赖，闭包条目（传递依赖）无资格进 `dependencies`，离线需求落空；且丢失 `sha256` 装前预验与 `reason` 元数据，并违反 §2 前向兼容规则（不改既有字段的类型与语义）。否决理由见 `../../docs/vendoring-guide.md` §5。
>
> **第二批已评估（实测背书）**：①「安装端预填充 pnpm store 以满足 registry 风格解析」已否决——用 `file:` 预热出的 store 条目不携带 integrity，registry 风格解析仍报 `ERR_PNPM_NO_OFFLINE_TARBALL`（可行做法是改 lockfile 的取件地址，见 v3 §8.3）；②「`vendor:` 键带来源（如 `vendor:github:owner/repo`）」已否决——内嵌后来源既不参与安装也不参与定位（定位改按 tarball 内 `name@version` 在 lockfile 里认节点），记来源只会让键语法复杂化；③「直接依赖在声明层本地化（`package.json` 写 `file:`）但不同步改 lockfile」已否决——实测 `ERR_PNPM_OUTDATED_LOCKFILE`（importer 与 `package.json` 的 specifier 必须一致）。

安装端本地化算法见 `../pack-structure/v3.md` §8。

## 13. dshVersions 兼容集（v5 r2）

- `dshVersions`：作者**实测过**的兼容版本**枚举集**。**枚举而非 semver range**——枚举 = 测过什么列什么；range 会诱导声明未实测的未来版本，且 DSH 版本带 `rc` 后缀、range 比较易错。
- **约束**：非空、每项为合法版本字符串、去重；`dshVersion` 同时出现时必须 ∈ `dshVersions`；两者全缺省时维持现状（取最新已装）。
- **安装决策（确定性，永有唯一答案）**：`dshVersions ∩ 本机已装 ≠ ∅` → 命中多个时优先 `dshVersion` 指定者、其次集合内最新；`= ∅` → 按 `dshVersion` 提示安装（与现行未装行为一致）。
- **可复现性措辞**：层栈依赖（`dependencies`）仍逐项钉死，仅运行时版本**有界浮动**于实测集。`dshVersions` 是作者实测声明，不是对未列版本的兼容承诺。
- 老消费者只读 `dshVersion`，行为不变（集合被忽略 = 现状）。

## 14. launchers 启动器兼容声明（v5 r2）

> 关联：`../launcher-registry.md`（canonical ID 认领表）、`../pack-structure/v3.md` §8.4（安装端判定表）。

`launchers`：`启动器 ID → 简式 | 全式` 的 map，缺省 = 通用包（现状不变）。**归一化规则：语义上只有全式，标量是糖**：

| 简式 | ≡ 全式 |
| --- | --- |
| `true` | `{ "supported": true }` |
| `"<version>"` | `{ "supported": true, "minVersion": "<version>" }` |
| `false` | `{ "supported": false }` |

- 全式字段**锁定三个，不得再增**：`supported`（✅ boolean，归一化后的唯一权威判定位）、`minVersion`（否，**最低版本要求**，比较语义「≥」，不精确钉死——启动器会自动更新）、`reason`（否，警告文案；`supported:false` 时强烈建议）。
- 未列出的 ID = 未声明（三态第三态）。
- 安装端判定表（含版本分支、警告放行不硬拒）见 `../pack-structure/v3.md` §8.4；本字段被老消费者忽略，照装即现状。

## 15. 结论

> v5 的本质是**统一的整合包契约**：用 `type` 在「单 profile 层栈」（`profile`，即 v4）与「整个 DSH_HOME 快照」（`dshhome`，多 profile + 全局 preset / skill / 指令）之间切换，`files[]` 把重内容纳入「指针 + sha256」闭环。两种形态共享 `dshVersion` 精确、多语言元数据与可复现约束，由 `.dspack` v3 容器统一承载。
