# Manifest v1 规格说明（已废弃）

> 状态：**已废弃**。当前仓库不再生成或安装 v1 包，仅在安装时做**兼容性检测**（拒绝）并保留**展示降级辅助**（`extractPlugins`）。
>
> 代码定位：`ModPack-CLI/packages/modpack/src/manifest.js`（降级辅助）、`install.js`（迁移判断）、`test/manifest.test.js`（断言）。
>
> ⚠️ 说明：v1 的原始实现已随早期 git 历史重建而丢失。本文对 v1 的描述由现有代码中的迁移判断、降级辅助函数与注释**反向推导**，无法核实的内容显式标注为「推断」。

---

## 1. 概述

v1 是整合包 `manifest.json` 的早期格式，核心是**压平的插件清单 `plugins[]`**。它把「层栈」与「npm 依赖」两个正交维度混在同一张 `{ name, version }` 列表里，因而无法表达 DSH 的加载语义，最终被 v2 取代。

---

## 2. 格式结构

> 结构为**推断**，来自 `install.js:validateManifest` 的迁移判断与 `manifest.test.js` 的断言。

```jsonc
{
  "manifestVersion": 1,          // 推断：存在版本号，但当前校验逻辑不读它
  "name": "web",
  "version": "1.0.0",
  "plugins": [                   // ★ 压平的插件清单（v1 的核心字段）
    { "name": "@deepseek-ai/dsh-base", "version": "latest" },
    { "name": "dsh-browser-automation", "version": "^0.2.0" }
  ]
}
```

---

## 3. 字段清单

| 字段 | 类型 | 说明 |
|---|---|---|
| `manifestVersion` | number | 契约版本（推断为 1） |
| `name` | string | 包名 |
| `version` | string | semver |
| `plugins[]` | array | ★ 压平的插件清单，每项 `{ name, version }` |

其中 `plugins` 的生成语义（由 v2 遗留的 `extractPlugins` 推断）：

- `dependencies` 中的包携带精确版本；
- `dsh.profile.bundles` 中的包无版本，记为 `"latest"`；
- 同名去重，`dependencies` 的版本胜出。

---

## 4. 核心缺陷

驱动的根本问题是 DSH 的加载语义：**「安装了插件」≠「加载了插件」**。

DSH Profile 采用**显式引用制**（源码出处 `apps/cli/src/plugin.ts`、`packages/boot/app-boot/src/profile.ts`）：只有进了 `dsh.profile.bundles` 的包，才会被 `loadProfile` 按序应用其 `cordis.patch.yml` 补丁层；只写在 `dependencies` 里却不在 `bundles` 里的包，会被 `pnpm` 装上，却**永远不被 DSH 加载**。

v1 的扁平 `plugins[]` 无法区分：

| 丢失的信息 | 后果 |
|---|---|
| 层栈顺序 | `loadProfile` 按序应用补丁层的语义无法表达 |
| 「层栈」与「依赖」的边界 | 无法区分「该加载」与「仅安装」的包 |
| 配置原文 | `cordis.patch.yml` 的注释、`!!js` 表达式、覆盖顺序无法无损传输 |
| bundle 版本语义 | 非依赖的层栈只能记 `version: "latest"` |

因此安装 v1 包时，无法可靠重建出一个「装完即可被 DSH 正确加载」的 Profile——这是 v1 被废弃的根本原因。

---

## 5. 废弃与迁移

`validateManifest`（`install.js:95`）通过字段存在性判断 v1，安装时**直接拒绝**：

```js
if (m.plugins !== undefined && m.bundles === undefined) {
  errors.push('manifest 是旧版格式（plugins 字段），请用新版 modpack pack 重新导出');
}
```

> 判定依据是「有 `plugins` 且无 `bundles`」，**不读 `manifestVersion` 数值**（详细讨论见 `v2.md` 的「已知边界」）。

---

## 6. 遗留：降级辅助 `extractPlugins`

v1 的「压平插件清单」在 v2 时代作为**展示用**辅助函数保留（`manifest.js:69`），不再作为持久化格式：

- `dependencies` 优先，携带精确版本；
- `dsh.profile.bundles` 补缺，无版本记为 `latest`；
- 同名去重，dependencies 版本胜出。

它是 v1 语义在 v2 代码库中的唯一残余，仅用于展示/调试，不写回 `manifest.json`。

---

## 7. 结论

> v1 = 扁平快照，丢失了层栈顺序、层栈/依赖边界与配置原文三个关键维度，与 DSH 的显式引用加载语义不匹配，因此被 v2 的「三分离层栈契约」取代。详见 `v2.md`。
