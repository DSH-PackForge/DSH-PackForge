# Manifest v2 规格说明（历史，启动器兼容导入）

> 状态：**历史好用的格式之一**。整合包 = 「层栈契约」，不是扁平快照。
>
> 代码定位：`ModPack-CLI/packages/modpack/src/manifest.js`（生成）、`install.js`（校验 / 应用 / 对账）、`indexfile.js`（索引映射）。

---

## 1. 概述

v2 把 DSH Profile 的三个正交维度拆开存——`bundles`（加载顺序）/ `dependencies`（npm 版本）/ `patch`（配置原文）——并在安装时作为「唯一事实源」重建 Profile，从而根治「装了 ≠ 加载」的静默故障。

---

## 2. 完整 schema

`buildManifest()`（`manifest.js`）产出的完整结构：

```jsonc
{
  "manifestVersion": 2,                       // 契约版本
  "name": "web",                              // slug：sanitizeSlug(profile.name)
  "displayName": "网页开发助手",               // 展示名，去掉 dsh-* 前缀
  "version": "1.0.0",                         // semver
  "description": "...",
  "author": "hxh",                            // opts -> package.json -> git config user.name
  "icon": "icons/logo.png",                   // 归档内相对路径
  "dshVersion": ">=0.1.0",                    // 运行所需的 DSH 版本约束
  "profileName": "web",                       // 原始 Profile 目录名（打包时不做 slug）

  "bundles": [                                // ★ 有序层栈（dsh.profile.bundles 原文，去重）
    "@deepseek-ai/dsh-base",
    "@deepseek-ai/dsh-web-app"
  ],
  "dependencies": {                           // ★ 版本化 npm 依赖（package.json.dependencies）
    "dsh-browser-automation": "^0.2.0"
  },
  "patch": "# patch layer ..."                // ★ cordis.patch.yml 原文（含注释/!!js，无损）
}
```

---

## 3. 字段清单

| 字段 | 来源 | 说明 |
|---|---|---|
| `manifestVersion` | 硬编码 `2` | 契约版本 |
| `name` | `opts.name` \|\| profile.name，经 `sanitizeSlug` | 规范化小写 slug |
| `displayName` | `opts` 覆盖，否则 `niceName()` | 去掉 `dsh-profile-`/`dsh-` 前缀 |
| `version` | `opts.version` \|\| package.json.version \|\| `1.0.0` | semver |
| `description` / `author` | opts → package.json → `git config user.name` | 作者兜底到 git |
| `icon` | 扫描第一个匹配 `icons?/*.{png,jpg,webp,ico,svg}` 或 `logo.*` | 归档内相对路径 |
| `dshVersion` | `opts.dshVersion` \|\| `>=0.1.0` | DSH 版本约束 |
| `profileName` | `profile.name` 原始值（未 slug） | 安装时建议目录名 |
| `bundles` | `pkg.dsh.profile.bundles`，去重、只留非空字符串 | ★ 有序层栈 |
| `dependencies` | `pkg.dependencies` 原样拷贝 | ★ 版本化依赖 |
| `patch` | `cordis.patch.yml` 原文整文本 | ★ 无损保真 |

---

## 4. 三分离设计

| 字段 | 对应 DSH 结构 | 版本语义 | 用途 |
|---|---|---|---|
| `bundles` | `dsh.profile.bundles` | **无版本**，顺序即加载顺序 | 层栈 |
| `dependencies` | `package.json.dependencies` | 有 version range | 驱动 `pnpm install` |
| `patch` | `cordis.patch.yml` | 原文整文本 | 配置补丁，字节级保真 |

### 关键原则

- `patch` 不做 `JSON.parse` → 重写，而是整串搬运，保证注释、`!!js` 表达式、覆盖顺序全部无损。
- `bundles` 的**顺序**承载 DSH `loadProfile` 的补丁层应用顺序，因此去重但**保持原序**。
- `dependencies` 只取 `package.json.dependencies`（运行时），**不含 devDependencies**。

## 5. 生命周期（4 阶段闭环）

```
① 生成 pack   ² 校验 install   ³ 落盘 apply   ⁴ 对账 reconcile
buildManifest → validateManifest → applyManifestToProfile → reconcileProfile
```

| 阶段 | 函数 | 关键行为 |
|---|---|---|
| ① 生成 | `buildManifest` | 读 Profile → 三分离 → 连同扫描文件写 `manifest.json` 进 `.tgz` |
| ② 校验 | `validateManifest` | 结构校验：name/version 非空、bundles 字符串数组、dependencies 对象、patch 字符串、拒绝 v1 |
| ③ 落盘 | `applyManifestToProfile` | **manifest 是唯一事实源**：覆盖重建 `package.json` 的 `dependencies` / `dsh.profile.bundles`，并写回 `cordis.patch.yml`；非契约字段（name/private/scripts）保留快照 |
| ④ 对账 | `reconcileProfile` | 安装 `pnpm install` 后校验层栈：见下 |

> 完整性闭环：manifest 权威覆盖 tgz 内的 `package.json` 快照；而 `sha256` 覆盖整个 `.tgz`（含 manifest），所以「篡改 manifest」会被索引里的 `sha256` 兜住。

### 对账三态（`reconcileProfile`）

判定标准对齐 DSH 源码：**Bundle 的唯一判据是 `dsh.bundle.patch` 字段存在**。

| 结果 | 条件 | 处理 |
|---|---|---|
| **missing** | 层栈中「同时是依赖」的包，装完无 `dsh.bundle.patch` 声明 | 报错 + **删除整个 Profile 回滚** |
| **added** | 依赖里声明了 `dsh.bundle.patch` 却没进层栈 | 自动补进 `bundles` 并写回 |
| 模板型 bundle | 仅在 `bundles`、不在 `dependencies` | 跳过验证，由 DSH 安装目录 fallback 兜底 |

---

## 6. 与索引 `index.json` 的关系

`buildEntry()`（`indexfile.js`）把 manifest **平铺**成索引条目：

| manifest 字段 | 是否进索引 | 语义迁移 |
|---|---|---|
| `bundles` / `dependencies` | ✅ 原样 | 市场页展示 / 筛选用 |
| `name` / `version` / `displayName` / `description` / `author` / `icon` / `dshVersion` | ✅ 原样 | 元数据 |
| `patch` | ❌ **不进入** | 只存在于 tgz，索引以 `sha256` 兜底完整性 |
| `manifestVersion` | ❌ 不进入 | 索引用独立的 `schemaVersion` |
| — | ✅ 新增 `category` / `downloadUrl` / `sha256` / `size` / `updatedAt` | 索引专属字段 |

## 7. 相对 v1 的变化

| v1 | v2 |
|---|---|
| 压平 `plugins[]`（name+version） | 三分离 `bundles` / `dependencies` / `patch` |
| 层栈顺序丢失 | 顺序保真 |
| 层栈与依赖混同 | 边界清晰 |
| 无配置原文 | `patch` 整文本无损 |
| 安装无法可靠重建层栈 | manifest 唯一事实源 + 安装后对账 |

详情见 `v1.md`。

## 8. 已知边界 / 待改进点

> 以下为对当前 v2 实现的观察，非阻断性缺陷，供后续迭代参考。

1. **`manifestVersion` 字段本身不被校验**：`validateManifest` 判断 v1/v2 依赖 `plugins` 字段存在性，从不读 `manifestVersion` 数值。未来升 v3 时判断会变脆弱。
2. **`icon` 语义断裂**：manifest 里 `icon` 是「归档内相对路径」（如 `icons/logo.png`），`buildEntry` 原样抄进 `index.json`；但市场网页拿到的相对路径无法解析（图在 tgz 内、不在站上）。
3. **`profileName` 打包时未规范化**：`name` 已 slug，`profileName` 存原始目录名，脏归一化推迟到 install 的 `sanitizeSlug`，存在轻微不一致窗口。
4. **`bundles` 无版本的张力**：层栈不锁版本（符合 DSH 语义），但意味着「作者重新 pack」是 bundle 升级的唯一途径；`reconcile` 只验 `dsh.bundle.patch` 声明存在、不验版本，可能引入「模板型 bundle 被作者环境悄悄升级」的不可复现性。

---

## 9. 结论

> v2 的本质是把「扁平快照」升级为「层栈契约」：让 `bundles`（顺序）、`dependencies`（版本）、`patch`（配置原文）三者的语义边界在数据里可见，并在安装时以 manifest 为唯一事实源重建 Profile、安装后对账回滚，从而根治「装了 ≠ 加载」的静默故障。
