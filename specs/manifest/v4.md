# Manifest v4 规格说明（未来）

> 状态：**未来（尚未实现）**。v4 在 v3「可复现层栈契约」之上，新增 `type` 与可选 `files[]`，配合 `.dspack` 容器（见 `../pack-structure/v2.md`）支持「重内容按需拉取」。当前生成/导入仍以 v3 为主，本文为下一步实现的目标契约。
>
> 关联：`../manifest/v3.md`（v4 的前身，现行）、`../pack-structure/v2.md`（承载 v4 的容器）、`../index/index.md`（市场索引可跟进 `type`）。

---

## 1. 概述

v4 保持 v3 的全部硬约束（依赖坐标钉死精确版本 / commit sha、`dshVersion` 精确、`displayName` / `description` 多语言），在此基础上新增两点：

- **`type`**：区分「单个 profile 整合包」（`profile`）与未来的「整合包集合」（`collection`，预留）。
- **`files[]`**（可选）：mrpack 式下载清单，让**重内容**（模型、数据、非 npm/git 的二进制）不进包体，只记 `path + sha256 + size + urls[]`，安装时按需下载。

---

## 2. 字段定义

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `manifestVersion` | number | ✅ | 固定为 `4` |
| `type` | string | ✅ | `"profile"`（现行唯一值）；`"collection"` 预留（校验器拒绝）。缺省按 `"profile"` 兜底 |
| `name` | string | ✅ | 整合包标识（kebab-case），也是 `.dspack` 文件名前缀 |
| `version` | string | ✅ | 整合包自身版本号（semver） |
| `displayName` | string \| object | 否 | 同 v3：字符串或多语言 map |
| `description` | string \| object | 否 | 同 v3 |
| `author` | string | 否 | 作者 |
| `icon` | string | 否 | 图标（URL 或归档内相对路径） |
| `dshVersion` | string | 否 | **固定精确版本号**（同 v3）；缺省用本机最新已装版本 |
| `profileName` | string | 否 | 导入时创建的 profile 名；缺省 `pack` |
| `bundles` | string[] | ✅ | profile 层栈（`dsh.profile.bundles`，按序挂载） |
| `dependencies` | object | ✅ | 坐标 → 固定版本：npm 包钉精确版本，git 包为 `github:owner/repo` → commit sha |
| `patch` | string | 否 | patch 层；或由 `overrides/cordis.patch.yml` 携带（文件优先，见 pack-structure v2） |
| `files` | array | 否 | 下载清单（重内容），条目见 §3 |

---

## 3. files[] 下载清单

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `path` | string | ✅ | 安装后落在 profile 内的相对路径（`/` 分隔） |
| `sha256` | string | ✅ | 单文件 64 位十六进制哈希（DSH 统一用 sha256，不引入 sha1/sha512） |
| `size` | number | ✅ | 字节数，正整数 |
| `urls` | string[] | ✅ | 下载源（可多个镜像，依次尝试） |

> `files[]` 只负责「重内容按需拉取」；常规插件/依赖仍走 `bundles` + `dependencies`（npm / git），**不**写进 `files[]`。若某个 `files[]` 的 `path` 与 `overrides/` 内文件冲突，以 `files[]` 下载产物为准（覆盖）。

## 5. 相对 v3 的变化

| 字段 | v3 | v4 |
| --- | --- | --- |
| `manifestVersion` | 3 | **4** |
| `type` | 无 | `"profile"`；`"collection"` 预留（缺省按 `"profile"`） |
| `files` | 无 | 可选数组（`{ path, sha256, size, urls[] }`） |
| 其余全部字段 | — | 原样不变 |

---

## 6. 导入行为（启动器，目标）

1. 校验 `.dspack` 头部（见 pack-structure v2）→ 剥离头部解 ZIP → 读 `manifest.json`，校验 `manifestVersion === 4` 且 `type === "profile"`（`"collection"` 报「暂未支持」）。
2. 弹出确认框：实例名（默认当前语言的 `displayName`）、profile 名（默认 `profileName`，缺省 `pack`）。
3. `overrides/` 覆盖到 profile 根（`cordis.patch.yml` 等用户文件落地）。
4. 安装 `dshVersion` 指定的 DSH 版本 → 按 `dependencies` 转 `package.json` → `pnpm install`（优先 `--frozen-lockfile`）。
5. 逐条 `files[]` 下载到 `path`，逐个校验 `sha256` + `size`；任一失败删除已下文件并整体回滚。
6. `reconcileProfile` 对账（缺失 bundle → 回滚）。

---

## 7. 结论

> v4 的本质是「可复现的层栈契约 + 可定型的集合单元」：在 v3 钉死依赖与运行环境的基础上，用 `type` 标明整合包形态，用 `files[]` 把重内容也纳入「指针 + 哈希」的完整性闭环，配合 `.dspack` 容器让同一个包在任何机器上都能还原出字节级一致的 profile。
