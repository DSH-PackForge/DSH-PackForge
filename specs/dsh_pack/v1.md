# 插件数据和可选资源规范 v1

插件作者在已发布 npm 包的 `dsh_pack/paths.json` 声明自己的数据文件。打包端读取声明、识别 DSH 的 Provider、MCP 和技能，使用者逐项选择后，将选中的资源写入整合包根的四种 JSON 文件。[容器布局](../pack-structure/v4.md)

## 1. 插件声明数据位置

`dsh_pack/paths.json` 可以是一个对象或对象数组。使用 npm 包的 `files` 白名单时，须包含 `dsh_pack/`。声明使用 `name`、可选 `desc` 和非空字符串数组 `paths`。名称与简介支持纯文本及语言映射。

```json
[{
  "name": { "zh-CN": "界面布局", "en": "Layout" },
  "desc": "保存面板宽度与排列顺序",
  "paths": ["./profiles/<profile>/data/"]
}]
```

路径以 DSH_HOME 为根，使用 `/`。`./profiles/<profile>/data/` 指向所选 profile 的 `data` 目录。`<profile>` 必须独占一个路径段；`<profile>/config/example` 等价于 `profiles/<profile>/config/example`。文件和目录均可声明。包含 profile 变量的规则按每个 profile 单独生成，纯全局规则在同一整合包内只生成一次。禁止绝对路径、上级目录、控制字符、系统保留目录、凭据和符号链接；层栈文件、依赖清单、锁文件、技能及预设由相应机制处理。一个文件不得归属两个选中条目。

导出器将所有已声明的路径移出常规覆盖目录。选中的文件写入 `extension-data/path/`，未选中的文件随本机保留。旧版包没有声明时按其原格式读取。[完整插件声明](../../examples/v6/plugin/dsh_pack/paths.json)

## 2. 四个归档文件

这些文件是独立的 UTF-8 JSON。`scope` 为 `home` 或 `profile:<名称>`。`name`、`desc` 供预览显示并支持翻译，标识由 `kind`、`scope`、`id` 共同确定。路径条目还包含插件 ID。一个作用域中的同类标识必须唯一。

| 文件 | 根结构 | 条目字段 |
| --- | --- | --- |
| `path.json` | `{"plugins":{"<插件ID>":[...]}}` | `kind:"path"`，`plugin`、`id`、`scope`、`key`、`name`、`desc`、`paths[]`、`files[]`，可带 `directories[]` |
| `provider.json` | `{"items":[...]}` | `kind:"provider"`，`id`、`scope`、`key`、`name`、`desc`、`value`、`credentialRefs[]`，可带配置所属行 |
| `mcp.json` | `{"items":[...]}` | `kind:"mcp"`，同上；`value` 表达 MCP 客户端行，含行 ID、模块名和连接配置 |
| `skill.json` | `{"items":[...]}` | `kind:"skill"`，`scope`、`id`、`key`、`name`、`desc`、`mode`、`digest`；其余字段取决于来源模式 |

### 插件数据

路径条目的 `id` 是 `paths.json` 中规则从 0 起的位置，用字符串编码。`key` 使用 `path:<scope>:<插件ID>:<id>`。每个文件记录其原始 `path`、所属规则内路径的数组下标 `index`、相对于该目录的 `tail`（单文件为空字符串）、`sha256` 与 `entry`。`entry` 必须为 `extension-data/path/<sha256>`。安装端根据模板和实际选定的 profile 名重新计算目标，校验文件边界和字节摘要后写入。[path.json 示例](../../examples/v6/profile/path.json)

`directories` 记录选中的空目录，包括空的规则根和树内空子目录。每项仅包含 `path`、`index`、`tail`。空规则根的 `tail` 是空字符串，树内空目录的 `tail` 是相对于规则根的目录名。文件与空目录共用目标命名空间，禁止同名（含大小写差异）或在某一文件、空目录下再声明子项。缺省 `directories` 等同于空列表。安装时按实际 profile 名和目录位置重建父目录及选中的空目录，已有目录中的本机文件保持原样。更新撤销声明时仅清理安装器创建、无其他包使用且仍为空的目录。本机已删除的目录可保持删除；安装失败按事务撤回新建目录并恢复先前移除的空目录。

### Provider 与 MCP

Provider 按服务商 ID 从相应 Cordis 补丁中提取，MCP 按服务实例 ID 提取。`key` 分别为 `provider:<scope>:<id>` 和 `mcp:<scope>:<id>`。`value` 保存可移植的配置。参考实现识别 `llm-pi-ai` 的 `config.providers`、DeepSeek API key 配置、独立 MCP 客户端行和 MCP 管理器的 `config.servers`。`owner` 标记原配置行，`binding` 与 `insertOwner` 可辅助恢复原插入位置。MCP 支持 `stdio` 与 `streamable-http`。

导出时从基础补丁中剥离这些配置，并删除 API 密钥实值。Provider 可使用 `apiKeyEnv` 指定本机变量；MCP 的环境项与请求头使用 `{"$credential":"DOCS_TOKEN"}` 引用，带认证前缀时可记录 `"prefix":"Bearer "`。`credentialRefs` 必须与配置中的引用相符。安装预览显示引用名、目标端点、是否已存在同名配置和是否缺少凭据。确认后方可复用本机凭据；用户可以输入新值或跳过该项，未确认的实值不写入项目或市场。支持的本机来源包括进程环境、DSH 凭据存储和相应目录的 `.env`。用其他来源覆盖同名配置须明确选择。[provider.json 示例](../../examples/v6/profile/provider.json) · [mcp.json 示例](../../examples/v6/dshhome/mcp.json)

stdio 参数中的密钥选项和认证头也可使用凭据引用；导入时恢复选项名与 Basic/Bearer 前缀。含内联脚本、签名地址或无法安全拆分的认证信息时，导出器从基础补丁中移除该配置，并在选择导出时提示原因。MCP 的 `serverName` 在实际生效的 profile 内应唯一。导入器会检查 HOME 与当前 profile 共同启用的服务器，同名冲突可在预览中处理。不同 profile 可分别使用同名服务。

### 技能

全局技能使用 `scope:"home"` 与 `key:"skill:home:<id>"`，对应共享的 `DSH_HOME/skills`。整机包也支持 `scope:"profile:<profile>"`、`key:"skill:profile:<profile>:<id>"`，用于各 profile 的独立技能槽，同名技能可分别安装。单 profile 导出的可移植技能使用 `skill:home:<id>`，安装端映射到实际目标。目录技能须含 `SKILL.md`，平铺 Markdown 技能以 `flat:true` 标识。技能目录下的 `.git` 和 `.dsh-skill.json` 不随归档分发。

| `mode` | 来源与校验 |
| --- | --- |
| `embedded` | 原文件写入 `extension-data/skill/<sha256>`，`files[]` 逐项记录相对 `path`、`entry` 与 `sha256`。适用于本地编写或已修改技能 |
| `fixed` | `repository` 指定 Git 地址，`subdir` 可指定仓库子目录。`ref` 和 `commit` 是同一个完整 Git commit SHA，安装端校验所取提交 |
| `track` | `repository`、`subdir` 与 `ref` 标识被跟踪的仓库、分支或标签。`commit` 记录导出时实际解析的提交；安装或更新时重新解析所选引用 |

`repository` 接受无嵌入凭据的 HTTPS 或 SSH Git 地址，`repository#/子目录` 可写为独立 `subdir`。导出远程技能前验证其可定位性和本地修改，不一致时选择内嵌模式。`digest` 的计算步骤是按相对路径排序，将各文件记为 `[路径, 文件SHA256]`，把这些二元组数组序列化为无缩进 JSON，再取 UTF-8 字节的 SHA-256。内嵌模式校验全部文件和整棵树的摘要；跟踪模式同时显示原提交与跟踪引用，允许上游更新。[skill.json 示例](../../examples/v6/dshhome/skill.json)

## 3. 导出、安装与发布

工作区选择使用 `selection.paths`、`selection.providers`、`selection.mcp`、`selection.skills`。前三项可记录资源键或含 `key` 的对象；技能可额外记录 `mode`、`repository`、`subdir` 和 `ref`。名称和简介允许人工调整。资源选择及凭据输入分开保存，只有可分发内容进入归档。[工作区配置](../workspace-config/v1.md)

读取器须检查声明、目标路径和归档数据的对应关系。已有本机条目应显示冲突，支持保留、替换及跳过，缺少所需凭据时默认跳过。市场摘要只用于浏览，安装端以通过完整性校验的归档内清单为准。
