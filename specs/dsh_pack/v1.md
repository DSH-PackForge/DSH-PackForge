# 插件数据与可选资源规范 v1（dsh_pack v1，现行）

> 状态：**现行**。本规范定义插件作者声明数据路径的方式，以及整合包中四类可选资源清单的格式与导出、安装规则。
>
> 关联：[容器规范 v4](../pack-structure/v4.md) · [清单规范 v6](../manifest/v6.md) · [工作区配置 v1](../workspace-config/v1.md)

插件作者可在已发布 npm 包的 `dsh_pack/paths.json` 中声明自身的数据文件位置。打包端读取插件声明，并自动识别 DSH 的模型服务商（Provider）、MCP 服务与技能（Skill）；用户在导出时逐项勾选后，选中的资源将写入整合包根目录对应的四种 JSON 清单文件中。

## 1. 插件声明数据路径（`dsh_pack/paths.json`）

`dsh_pack/paths.json` 的根结构可以是单个对象或对象数组。若 npm 包使用了 `files` 白名单字段，须将 `dsh_pack/` 纳入其中。每条声明包含 `name`、可选的 `desc` 以及非空字符串数组 `paths`，其中 `name` 与 `desc` 均支持纯文本及多语言映射（locale map）。

```json
[{
  "name": { "zh-CN": "界面布局", "en": "Layout" },
  "desc": "保存面板宽度与排列顺序",
  "paths": ["./profiles/<profile>/data/"]
}]
```

### 路径语法与约束

- 路径以 `DSH_HOME` 为根，统一使用正斜杠 `/` 分隔。`./profiles/<profile>/data/` 指向当前所选配置档（profile）的 `data` 目录；`<profile>` 必须独占一个完整路径段，且 `<profile>/config/example` 等价于 `profiles/<profile>/config/example`。
- 文件与目录均可声明。含 `<profile>` 占位符的规则按每个配置档分别生成条目，纯全局规则在同一整合包内仅生成一次。
- 禁止使用绝对路径、上级目录跳转（`..`）、控制字符、系统保留目录、凭据文件与符号链接；层栈配置、依赖清单、锁文件、技能与预设由各自专用机制处理。同一个文件不得同时归属两个已选中的条目。
- 导出器会将所有已声明的路径从常规 `overrides/` 覆盖目录中移出：选中的文件写入 `extension-data/path/`，未选中的文件仅保留在本机。若旧版整合包未包含此类声明，仍按原格式直接读取。[完整插件声明示例](../../examples/v6/plugin/dsh_pack/paths.json)

## 2. 四类可选资源清单

四类清单均为独立的 UTF-8 JSON 文件。其中 `scope` 取值为 `home` 或 `profile:<名称>`；`name` 与 `desc` 用于预览展示并支持多语言翻译；资源标识由 `kind`、`scope` 与 `id` 共同确定（路径条目还包含插件 ID `plugin`），同一作用域内的同类标识必须唯一。

| 文件 | 根结构 | 条目核心字段 |
| --- | --- | --- |
| `path.json` | `{"plugins":{"<插件ID>":[...]}}` | `kind:"path"`，`plugin`、`id`、`scope`、`key`、`name`、`desc`、`paths[]`、`files[]`，可选 `directories[]` |
| `provider.json` | `{"items":[...]}` | `kind:"provider"`，`id`、`scope`、`key`、`name`、`desc`、`value`、`credentialRefs[]`，可附带原配置归属信息 |
| `mcp.json` | `{"items":[...]}` | `kind:"mcp"`，同上；`value` 描述 MCP 客户端配置条目，含条目 ID、模块名与连接参数 |
| `skill.json` | `{"items":[...]}` | `kind:"skill"`，`scope`、`id`、`key`、`name`、`desc`、`mode`、`digest`；其余字段随来源模式变化 |

### 2.1 插件数据（`path.json`）

- 路径条目的 `id` 为该规则在 `paths.json` 中从 `0` 起的数组下标（以字符串编码），`key` 格式为 `path:<scope>:<插件ID>:<id>`。
- `files[]` 中每个文件记录原始 `path`、所属规则内 `paths` 数组的下标 `index`、相对该规则根的路径 `tail`（单文件规则为空字符串）、`sha256` 与 `entry`；`entry` 固定为 `extension-data/path/<sha256>`。安装端根据路径模板与实际目标配置档名重算落点，校验路径边界与字节摘要后写入。[path.json 示例](../../examples/v6/profile/path.json)
- `directories[]` 记录已选中的空目录（含空的规则根目录与目录树内的空子目录），每项仅包含 `path`、`index`、`tail`（空规则根的 `tail` 为空字符串，子目录为其相对规则根的目录名）；缺省等同于空列表。
- 文件与空目录共享目标命名空间，禁止同名（含仅大小写不同）或在已有文件、空目录下再声明子项。安装时按实际配置档名重建父目录与空目录，已有目录中的本机文件保持不变；更新时若撤销了某条声明，仅清理由安装器创建、无其他包占用且仍为空的目录（本机已删除的目录保持删除状态）。若安装失败，则按事务撤回新建目录并恢复此前移除的空目录。

### 2.2 模型服务商（Provider）与 MCP 服务

- 模型服务商按服务商 ID 从对应 Cordis 补丁中提取，MCP 服务按服务实例 ID 提取；`key` 分别为 `provider:<scope>:<id>` 和 `mcp:<scope>:<id>`，`value` 保存可移植配置。参考实现支持识别 `llm-pi-ai` 的 `config.providers`、DeepSeek API Key 配置、独立 MCP 客户端条目以及 MCP 管理器的 `config.servers`；`owner` 标记原配置归属，`binding` 与 `insertOwner` 用于辅助还原原插入位置。MCP 传输方式支持 `stdio` 与 `streamable-http`。
- 导出时须从基础补丁中剥离上述配置，并剔除 API 密钥等实值。模型服务商可通过 `apiKeyEnv` 指定本机环境变量；MCP 的环境变量与请求头可使用 `{"$credential":"DOCS_TOKEN"}` 进行引用，携带认证前缀时可附加 `"prefix":"Bearer "`。`credentialRefs` 列表必须与配置中的实际引用完全一致。
- 安装预览须展示凭据引用名、目标端点、本机是否已存在同名配置以及是否缺少凭据。用户为当前资源输入的新值优先。对留空的引用，须经用户确认才可复用本机凭据，依次查找 DSH 凭据存储、进程环境变量、DSH 启动工作目录的 `.env` 和 `DSH_HOME/.env`。用户可逐项跳过资源。凭据实值仅留在本机，覆盖同名配置须经用户明确选择。[provider.json 示例](../../examples/v6/profile/provider.json) · [mcp.json 示例](../../examples/v6/dshhome/mcp.json)
- `stdio` 启动参数中的密钥选项与认证头同样支持凭据引用，导入时会自动恢复选项名与 `Basic ` / `Bearer ` 前缀。若配置包含内联脚本、签名 URL 或无法安全拆分的认证信息，导出器会将其从基础补丁中移除，并在选择导出界面提示原因。MCP 的 `serverName` 在实际生效的配置档内须保持唯一；导入器会检查 `DSH_HOME` 与当前配置档同时启用的服务，并在预览中处理同名冲突（不同配置档之间允许各自使用同名服务）。新增一个 MCP 服务时须保留其他配置层已启用的服务。DSH 的管理器补丁会替换整个配置，导入器可为选中的服务创建独立 MCP 客户端，并在预览中告知用户其管理位置。此方式须保留服务名称、启停状态与凭据引用，并检查组合后生效的服务名是否冲突。同一作用域中可编辑的同名配置可由用户明确替换。遇到其他配置层占用名称时，导入预览须指出冲突。若离线安装时无法定位宿主内置配置，则标记为待实际启动时核验。

### 2.3 技能（Skill）

全局技能使用 `scope:"home"` 与 `key:"skill:home:<id>"`，安装至共享的 `DSH_HOME/skills`；`dshhome` 形态还支持 `scope:"profile:<profile>"` 与 `key:"skill:profile:<profile>:<id>"`，对应各配置档独立的技能目录，允许不同配置档分别安装同名技能。单配置档导出的可移植技能统一使用 `skill:home:<id>`，安装端会将其映射至实际目标位置。目录形式技能须包含 `SKILL.md`，单文件平铺 Markdown 技能以 `flat:true` 标识。技能目录下的 `.git` 与 `.dsh-skill.json` 不随归档分发。

| `mode` | 来源与校验规则 |
| --- | --- |
| `embedded` | 将原始文件写入 `extension-data/skill/<sha256>`，`files[]` 逐项记录相对 `path`、`entry` 与 `sha256`；适用于本地编写或已修改的技能 |
| `fixed` | 通过 `repository` 指定 Git 仓库地址，可选 `subdir` 指定子目录；`ref` 与 `commit` 须为同一个完整的 Git commit SHA，安装端严格校验拉取结果 |
| `track` | 通过 `repository`、`subdir` 与 `ref` 标识被跟踪的仓库、分支或标签；`commit` 记录导出时实际解析的提交，安装或显式更新时重新解析所选引用 |

- `repository` 仅接受不含内嵌凭据的 HTTPS 或 SSH Git 地址，`repository#/子目录` 写法会规范化为独立的 `subdir` 字段。导出远程技能前须校验其可定位性与本地修改状态，若本地与远端不一致则应选用 `embedded` 内嵌模式。在支持 POSIX 权限的文件系统上，安装及更新远程技能时应保留 Git 记录的可执行位。
- `digest` 的计算方式：将全部文件按相对路径排序，依次记为 `[相对路径, 文件SHA256]` 二元组，将二元组数组序列化为无缩进的 JSON 字符串，再对其 UTF-8 字节计算 SHA-256。内嵌模式校验全部文件及整棵目录树的摘要；跟踪模式同时展示原提交与跟踪引用，允许随上游更新。[skill.json 示例](../../examples/v6/dshhome/skill.json)

## 3. 导出选择、安装与发布

- 工作区配置使用 `selection.paths`、`selection.providers`、`selection.mcp` 与 `selection.skills` 保存勾选状态：前三项可记录资源键字符串或含 `key` 的对象，技能项可额外记录 `mode`、`repository`、`subdir` 与 `ref`，名称与简介均允许作者手动调整。资源选择与凭据输入分开保存，仅可分发内容进入归档。[工作区配置 v1](../workspace-config/v1.md)
- 读取器须校验声明、目标路径与归档数据的一致性；若本机已存在同名条目则展示冲突，支持保留、替换或跳过，缺少必需凭据时默认跳过。市场展示的 `resources` 摘要仅作浏览参考，安装端一律以通过完整性校验的归档内清单为准。
